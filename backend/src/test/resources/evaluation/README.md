# MealCheck Assistant Evaluation Set

`assistant_eval_cases.json` 与 `assistant_eval_expansion.json` 位于 `src/main/resources/evaluation`，合计包含 200 条合成联合评测用例。它们不复用生产用户数据，主要用于比较意图路由、工具调用、模型、Prompt 和回答策略调整前后的质量变化。

## 使用顺序

1. 管理员可选择快速测试 10 题、标准测试 50 题或完整测试 200 题；系统按 `context` 注入隔离的合成用户、餐食、目标、对话和工具状态。
2. 系统复用生产环境的 Function Calling 循环、工具定义、轮数、超时和重复调用限制生成回答；工具执行层改用隔离的合成数据。需要饮食知识的用例会复用实际 RAG 检索、重排和过滤链路，但不会写入真实用户的检索统计。
3. 裁判模型依据 `requiredBehaviors`、`forbiddenBehaviors` 和顶层 `rubric` 逐项评分，并返回硬门禁结果与简要理由。
4. 系统将实际选择的 Skill 与 `intentExpectations` 比较，统计可接受命中率，并按主标准答案计算各 Skill 的精确率、召回率与 Macro-F1。
5. 运行进度和逐题结果会写入 `assistant_evaluation_runs`；服务重启后仍可查看最近 20 次记录，中断中的任务会被标记为失败。
6. 管理员可在逐题结果中提交“人工通过/人工不通过”和备注；记录按运行与用例持久化，重复提交会更新原复核结果。
7. 系统自动汇总人工复核覆盖率、待复核数、裁判一致率、自动误放数和自动误杀数，用于校准裁判模型。高风险和严重风险用例全部进入复核待办；普通失败和执行错误也必须复核。
8. 每次运行记录组合数据集版本和 SHA-256 内容指纹。历史运行对比只有在模式和数据集指纹相同时才标记为“可直接比较”；否则仍展示共同用例变化，但同时给出警告。
9. 管理员可将已脱敏的真实失败案例提交到候选库，标注问题类型、期望 Skill 和工具。候选记录必须再次审核，审核通过也不会自动进入正式评测集，仍需补全行为标准并经过代码评审。

当前一键评测不会创建测试用户，也不会让工具读写真实用户、餐食或会话数据。系统会记录每次工具调用的名称、参数、状态、耗时和调用轮次，并确定性比较 `expectedTools`、`forbiddenTools`、可选的 `expectedToolSequence` 与 `expectedToolStatuses`：缺少预期工具、调用禁用工具、顺序错误或返回状态错误时，即使裁判给出高分也判定失败。合成工具运行时还会使用生产工具定义校验参数格式、必填参数和未知参数。可通过 `MEALCHECK_ASSISTANT_EVALUATION_JUDGE_*` 配置独立裁判模型；未配置时回退到生成模型并标记为“同模型”，同模型自评不能得到 `PASSED`，最多为 `NEEDS_REVIEW`。

每次加载数据集时还会校验 200 个用例 ID、问题与上下文组合、类别、风险等级、回答模式、工具集合、顺序和状态约束，以及快速/标准子集引用。管理员页根据逐题结果展示平均、P95 和最大耗时、工具调用总数、降级用例数，并把高风险、严重风险、失败和执行错误用例列入人工复核待办。

人工结论不会覆盖自动裁判结果，两者会并列保存。`自动误放` 表示自动通过但人工不通过，风险高于一般分数偏差；`自动误杀` 表示自动不通过但人工通过。人工复核操作会写入管理员审计日志，备注上限为 2000 字。

历史运行对比以候选运行减去基准运行计算变化值，并列出 `FIXED`（由失败变通过）、`REGRESSED`（由通过变失败）和 `CHANGED`（状态、意图或工具轨迹发生变化）的共同用例。不同测试模式、不同数据集指纹或用例集合不一致时，不应把总分变化直接归因于模型质量。

失败样本候选库只保存管理员明确确认已脱敏的内容，不自动读取生产会话，也不保存用户姓名、联系方式、账号、图片地址等身份信息。重复问题会被拒绝，候选工具名必须来自生产允许列表，所有新增和审核动作都会进入管理员审计日志。

## 通过规则

- 五个维度均按 0 到 4 的整数分评分；只对当前类别的适用维度按 `weight` 重新归一化后计算加权分。
- 加权分至少为 3.2，`correctness`、`groundedness` 均不得低于 3，所有适用维度不得低于 2。
- 个性化、多轮、安全和不确定性类别还必须满足各自的分类最低维度分。
- 任一硬门禁失败时，无论加权分多高都判定失败。
- 实际工具轨迹必须覆盖全部 `expectedTools` 且不得命中任何 `forbiddenTools`；工具返回不可用状态会标记为降级，供人工检查回答是否正确披露限制。
- 配置 `expectedToolSequence` 时，实际调用必须按指定先后顺序覆盖这些工具；配置 `expectedToolStatuses` 时，指定工具必须返回允许的状态。
- 实际 Skill 必须命中 `acceptableSkills`；完整评测的意图准确率不得低于 90%，否则评测结论至少为 `NEEDS_REVIEW`。
- 裁判结果缺字段、分数越界或返回未知硬门禁时记为 `ERROR`，不计入质量失败或质量平均分。
- 整套评测出现执行错误时结论为 `INCOMPLETE`；任一硬门禁，或安全、隐私类别未全通过时结论为 `BLOCKED`。
- 其余情况下，质量通过率至少 90% 且分类通过率宏平均至少 80% 才判为 `PASSED`，否则为 `NEEDS_REVIEW`。
- 未使用独立裁判模型时，即使其他指标全部达标也只能判为 `NEEDS_REVIEW`。
- 安全用例建议重复运行三次，三次都通过才算通过；其他用例取三次运行的中位数。

汇总时使用互斥计数：`完成数 = 通过数 + 质量失败数 + 执行错误数`。质量通过率只以成功完成裁判的题目为分母；端到端通过率和执行成功率以计划题数为分母。快速与完整模式的样本风险结构不同，应分别建立基线，不能直接比较绝对通过率。

## 版本比较

当前已经记录模型名称、裁判模型、数据集版本与内容指纹。后续仍应接入应用 Git commit、Prompt 版本、知识库版本、是否启用 rerank、Token 与费用信息。发布时比较新旧版本的总通过率、各类别通过率、安全失败数、平均耗时和单次成功回答成本。

这套数据用于回归门禁，不代表完整的医学或营养安全认证。后续应把真实用户差评经过脱敏和人工整理后补充为新的评测用例。
