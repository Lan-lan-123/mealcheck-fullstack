# 真实 API 修复与 50 人一分钟验收（2026-10-15）

**最终一轮达到本次主目标：50 个独立账号同时上传，50/50 首次接收、50/50 真实模型分析并保存，全部在 56.47 秒内取得成功终态。** 沿用阿里云百炼 `qwen3.8-max`，没有切换模型或使用规则建议代替模型结果。这是一轮本地隔离验收，不能直接解释为生产、公网、不同图片分布或持续流量的 SLA。

前序失败、24 消费者的 71.65 秒轮次和最终通过轮次全部保留，分别统计，不以成功重跑覆盖失败。

## 代码修复

1. `RemoteCallGuard` 统一在操作失败出口结算熔断计数，覆盖调用耗尽期限、重试退避阶段超过期限等路径；每个操作只记一次。局部拒绝、取消、线程中断和明确不可重试错误不记入这类失败。并发中较早启动的成功调用不能提前关闭另一调用刚触发的熔断。
2. `AiChatClient` 保留 deadline 异常类型，同时更新 AI 服务状态和高层失败指标。未发出的预算拒绝仍单独处理。
3. `AiHttpTransport` 对已发出但没有响应的调用记录缺失 usage，新增 timeout、IO、供应商 HTTP 状态等有限类别的失败指标和日志。日志不包含密钥、图片、完整请求或响应。预算结算或许可释放失败时仍尝试记录物理调用指标。
4. `AiCallPermitStore` 新增可配置的全站启动间隔 `MEALCHECK_AI_GLOBAL_MIN_START_INTERVAL_MILLIS`。数据库事务锁协调不同实例、用户、重试和 AI 功能；等待发生在事务外，不持锁休眠。等待请求先检查间隔，不反复执行两张表的清理及计数，降低竞争。默认 0，由可选部署配置启用 400 毫秒。
5. 新配置已接入普通和生产 Compose、两份环境示例。提供配套上传入口/缓冲/接单/消费设置的可选 `deploy/burst50/compose.yml`，不需要照搬隔离测试凭据或测试预算。

单次模型调用及含重试的 remote 期限仍为 60 秒，整条执行预算仍为 120 秒；本次没有通过单纯增加超时来取得成功。队列等待不包含在消费者开始执行后的这 120 秒中；验收端另外从上传发起开始统计 60 秒目标。

### 最终调用节奏及耗时

数据库保留的本轮 100 个调用准入起点覆盖约 41.85 秒，最小间隔 401.317 ms、最大 1304.696 ms，活跃许可最后为 0。最小间隔验证了全站平滑约束生效，不能将 40 个消费者理解成 40 次/秒请求。

本轮识别 HTTP 平均约 4.71 秒、最大 8.68 秒；建议平均约 3.13 秒、最大 4.19 秒。最长队列等待从上一轮约 31.04 秒降至约 15.68 秒。两轮识别平均耗时接近，改进主要体现在这两轮的排队和调度过程；消费者、间隔与数据库快速等待路径同时变化，不能单独量化某一项的因果贡献。

该结果说明此账号的 Max 在本轮测试中有能力完成这批请求。前序 8 个消费者未平滑发送时的超时根因仍未被供应商请求侧记录完整证实；不能把它笼统归因为阿里云整体容量不足，也不能据一次通过保证任意时段都一样。
