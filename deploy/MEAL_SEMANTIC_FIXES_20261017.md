# 图片属性与建议事实一致性修复（2026-10-17）

本轮按 Qwen3.7 Flash 图片测试暴露的问题完善提示词、输入表达、识别结果校验和建议输出校验。没有修改评分公式、权重、封顶规则或评分版本 `structured-foods-v5`，没有切换业务默认模型，也没有部署。

## 识别与核对

- 明确 `fried` 在本项目只表示油炸，不包含普通炒制、清炒或煎制；油炸与高油分别估计，无法判断时保留 null。
- 明确整根、整粒玉米与米饭、面条、土豆等采用 staple 分类。玉米沙拉、玉米汁等混合菜和饮品不能仅凭名称包含玉米就归为主食。
- 新增只用于模型识别入口的 `RecognitionSemanticValidator`。当油炸属性与炒、煎、蒸煮等线索冲突，或属性与明确的否定描述冲突时，将冲突属性设为未知，并记录 `reviewIssues`。不会把炒菜自动判成低油，不会因为油炸未知就清除独立的高油风险。
- 保留实际油炸、炒炸鸡等混合做法的明确证据；旧 fried/oily 数据仍按已有兼容逻辑读取。用户手动纠正的明确判断不会再次被模型入口规则覆盖。
- 玉米分类冲突时暂归 other 并要求核对，不直接替模型确认分类。已识别为 staple 的玉米保持不变。
- 结果页和快捷核对显示冲突原因，即使模型置信度很高也提示核对。可以分别选择油炸是／否／不确定，以及玉米主食／不确定。
- `reviewIssues` 随原有食物 JSON 保存，不新增数据库表。纠正时同名食物的未知或未填写属性继续保留对应待核对标记；用户明确回答后清除相应标记。改名后的食物不会沿用旧食物风险。

冲突说明包含模型原来的标记；后续评分与建议使用处理后的未知属性。分类未确认、独立高油仍为 true 等情况可能仍产生扣分，因此修复不等于一律提高评分。

## 建议与评分文案

- 建议输入将属性明确写为 `是(true)`、`否(false)`、`未知(null，待核对)`，不再将 false 弱化成“未标记”。附带本地生成的核对原因。
- 补充约束：不能将未知当成已存在风险，不能把一项食物的风险套到另一项，不能把鸡蛋或豆制品统称肉类，不能无依据推定用户吃了加工肉或长期依赖加工肉。
- 新生成的风险标签及评分明细改为“当前未识别到主食／蛋白质来源／蔬菜来源”，不据识别覆盖情况断言摄入量不足。低分摘要围绕实际触发的规则说明，不统一暗示存在油炸或高油。
- 新增 `MealAdviceConsistency`，针对本轮问题检查当前食物油炸／高油断言、蛋与肉类概念、加工肉事实或习惯，以及将结构评分当成摄入量测量的表达。允许明确的否定、待核对表述和未来餐食建议；“油炸或高油”组合标签只需其中一个属性得到支持。
- 命中检查时展示带说明的本地规则建议，再应用原有饮食偏好约束；不追加模型重试，不展示被拦截的原始建议。

这些检查是针对已知问题的保守规则，不是完整自然语言事实验证器，也不能确认图片中的实际油量、份量或隐藏配料。提示词实际生成效果仍需后续少量真实模型复测确认。

- 处理冲突后，`synth-001、002、004、005` 从 67 分恢复为 90 分；其他图片的分数保持不变，部分仍有独立高油风险。每份评分明细均与总分核对一致。
- 对原始输入及原始建议，新规则拦截 12 条：019、066 两条已知事实／概念问题，9 条摄入量措辞问题（此前 8 条之外，还包括 075），以及 055 将未知油炸当作风险依据的表述。
- 对已处理冲突的输入继续复用旧建议，会再拦截 004、005、043、044 四条，共 16 条。它们的旧建议依赖后来转为未知的属性；这是旧建议与新输入不一致，并非修改提示词后重新生成的失败率。
- 不再误拦“油炸=true、高油未知”或“高油=true、油炸未知”所支持的单纯“油炸或高油”组合标签；额外断言某一未知属性仍会被检查。

离线回放的来源为 `loadtests/results/qwen37-flash-20261017-1607/results.json`，即此前真实 Flash 输出。80 张餐食逐条比较“同一原始输入的当前评分”与存档分数，验证公式保持一致；随后模拟识别入口的语义处理，检查待核对项、评分明细与建议拦截。20 张非食物跳过评分。离线回放不会生成新建议，不能当作修改提示词后的模型准确率测试。
