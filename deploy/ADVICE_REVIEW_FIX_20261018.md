# 随机十图问题定位与修复（2026-10-18）

本轮修复 2026-10-17 随机十图测试发现的两处问题：044 的“高油风险未知”被项目校验误拦，以及 074 对新鲜香蕉提出没有具体依据的高油核对。没有修改评分公式、权重、识别属性、业务默认模型或历史记录，也没有部署。

## 定位结果

### 044：项目输出校验误拦

原始建议明确说炒鸡蛋、煎蘑菇的高油风险状态为未知，与输入 null 相符。旧 `MealAdviceConsistency` 仅匹配“食物名称附近出现高油”，没有判断这个风险词是否被“状态为未知”限定，因此错误回退到本地规则建议。

修复前编译快照的离线回放可重复得到 044 回退，证明这是项目判断问题，不是供应商请求失败。

### 074：输入表达与核对范围不够明确

识别备注描述新鲜香蕉切片，fried/highOil 均为 null，没有具体油炸或高油线索。旧提示把所有 null 写成“未知(null，待核对)”，没有区分“无法判断属性”与“有依据、值得向用户确认的风险”。模型于是建议核对香蕉高油，而输出侧没有限制这种多余要求。

这属于提示与输入引导不足、输出检查缺少核对范围；不能把 null 自动改成 false 来掩盖问题。

## 修改

- 对风险词、对应食物及局部限定语进行检查。“高油未知”只限定高油，不会让同句其他食物或油炸断言自动放行。保留“不是未知”“明确存在”等反例的拦截。
- 分开处理整餐风险、单个食物风险与预防性建议。整餐有一项油炸或高油风险不等于每种食物都有；“避免／减少／不过于油腻”等表达也不等于断言当前食物高油。
- 新增 `MealAdviceRiskPolicy`。只有属性未知且具备相关做法／油光等识别线索，或已有本地冲突标记时，才进入对应风险的核对清单。这个清单只是建议资格，不是风险确认，不产生扣分，也不改变原始三态属性。
- 提示输入改为“未知(null，不代表已确认风险)”，单独列出“有依据的风险核对项目”。明确不应仅因 null 就要求新鲜水果或普通饮品核对高油／油炸；有豆浆、豆腐时也不应暗示必须补肉蛋才有蛋白质。
- 输出侧只删除“唯一问题是无依据核对”的完整句子，保留其余建议。如果同句还夹带事实矛盾，保留该句交给事实校验并回退；如果删除后内容为空，也会清楚标记为规则建议。原有饮食偏好约束仍在最终输出上执行，不追加模型重试。

此校验针对中文单餐建议的已知问题，不是完整自然语言理解或营养事实验证器。食物名称识别以输入名称为主，复杂省略、别名和表达仍有边界；没有因修复这两例就宣称所有误拦已消除。
