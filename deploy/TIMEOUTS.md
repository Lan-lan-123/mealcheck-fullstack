# 异步主流程与同步兼容超时

图片分析使用 `POST /api/meals/analysis-requests` 提交，然后按原请求标识查询；AI 周报使用 `POST /api/reports/weekly/jobs` 提交，然后按原任务 ID 查询。刷新、网络恢复或查询超时后继续查询已有任务，前端不会自动重新提交。

`POST /api/meals/analyze` 保留同步兼容。助手问答仍同步返回。`GET /api/reports/weekly` 保留读取快照或本地规则统计的兼容行为，它本身不执行 AI 周报生成。

## 默认等待时间

| 层次 | 默认值 | 范围 |
| --- | --- | --- |
| 后端单次 AI 操作 | 120 秒 | 共享执行截止时间，包含内部模型调用和重试 |
| 前端容器 Nginx | 150 秒 | `proxy_read_timeout` / `proxy_send_timeout` |
| 宿主机 Nginx | 165 秒 | `proxy_read_timeout` / `proxy_send_timeout` |
| 浏览器长请求 | 180 秒 | 助手、同步图片分析、兼容周报读取、管理端单图识别 |
| 浏览器其他请求 | 75 秒 | 普通查询、异步任务提交及状态轮询 |

浏览器长请求路径由 `frontend/src/api/client.js` 明确列出。单次外部模型调用连同重试仍默认最多 60 秒，并受整个操作剩余时间限制。Function Calling 保留其更短的执行上限。

Nginx 的读写超时是两次读写之间的等待时间，并非整个 HTTP 请求的绝对时长。上述余量用于使非流式同步请求能够等到后端的结果或结构化 `504 / AI_DEADLINE_EXCEEDED`，避免代理在第 75 秒先结束等待。

## 后端截止时间的范围

同步图片分析从图片校验、解码开始使用同一个截止时间，贯穿识别、知识检索、建议生成和保存。异步图片分析与 AI 周报从工作线程开始执行计算预算；持久化队列等待不消耗这次执行预算。工作线程保留截止时间直到发布结果。

阶段边界和事务提交前检查截止时间。超过期限的图片分析不提交餐食记录，事务回滚时清理暂存图片；过期周报不发布快照，并沿用原任务的失败及重试策略。正常期限内仍允许既有本地降级结果。

带幂等键的同步分析也保持截止上下文到保存完成；缓存合并的等待者使用自己的剩余期限并支持中断，超时不取消共享生产任务。供应商的 Retry-After 超过当前期限时会保留给周报任务的持久化重试。具体策略见 [后端代码完善](BACKEND_IMPROVEMENTS.md)。

这些是协作式截止检查：本地解码、文件写入和数据库操作依赖各自的约束及超时，检查会在操作返回时生效。120 秒不包含请求体上传、认证等前置阶段，也不保证立即中断所有底层操作。浏览器取消等待不代表后台任务或供应商已停止执行，不能据此判断未产生调用费用。

## 部署与自定义

前端容器需要重新构建并重建，才能更新 Nginx 配置及浏览器资源。宿主机配置参考 `deploy/nginx/mealcheck.conf.example` 更新，先执行 `nginx -t`，通过后再 reload。如果使用额外的 ALB、CDN 或网关，也需要检查它的上游等待时间。

`MEALCHECK_AI_OPERATION_TIMEOUT_SECONDS` 仍允许显式自定义；如果提高到超过默认 120 秒，需要同时调整容器代理、宿主机代理和浏览器长请求时间，保持逐层留有余量。只更改后端环境变量不会自动改变其他层。本次调整不修改每日调用额度或费用限制。

## 验证

后端执行 `mvn verify -Pintegration`，覆盖解码后截止、外部调用前截止、过期建议禁止保存、事务提交前过期回滚，以及周报超时不发布结果。前端执行 `npm test`、`npm run build` 和 `npx playwright test e2e/meal-flow.spec.js e2e/task-progress.spec.js`，覆盖长请求期限、普通查询期限、用户取消和异步流程。

两层真实 Nginx 的验收工具是 `tools/test_proxy_headers.py`；指定 `--slow-seconds 80` 验证延迟响应可以穿过两层代理，同时验证后端 504 响应完整保留。该工具使用本地模拟后端，不调用付费模型。

2026-10-10 本地验收：后端 241 项单元及 HTTP 测试、68 项 PostgreSQL 集成测试通过；前端 28 项测试和生产构建通过；10 项浏览器流程测试通过；真实两层 Nginx 的 80 秒响应、504 透传及原有限流/转发信任检查通过。浏览器流程使用模拟 API，代理验收使用模拟后端，不代表真实供应商的延迟或吞吐表现。
