# 知识源跨实例同步

## 行为

V36 新增 `knowledge_source_sync`，按 source 记录数据修订号、完成指纹、目标指纹、向量签名、实例、执行凭证、租约和最后错误。知识片段的内容写入、删除及清空会在同一事务推进对应源的修订号；命中次数不推进修订号。

自动初始化和两个管理员重建入口都经由 `PgVectorKnowledgeService.syncSource` 争取同一源的租约。同一源正在同步时，其他执行返回 409；后台维护把它视为正常等待，下次轮询再检查，不打印重复键错误堆栈。不同源可以并行准备向量。

完成指纹包含分块内容、顺序、键、token 数、源版本及向量配置。同版本自动启动直接跳过计算和发布，不刷新完成时间，也不批量清空检索缓存。检索继续使用原有事务提交的缓存修订号。

## 写入及故障边界

向量计算在事务外进行。每处理一片之前用短事务续租；默认租约 120 秒，配置范围 2–600 秒，应大于单次向量调用的最长执行时间并留出余量。配置为 `MEALCHECK_KNOWLEDGE_SOURCE_SYNC_LEASE_SECONDS`，普通、生产 Compose 及环境示例均已接入。长时间停顿后原执行不能复活过期租约。

发布使用短事务，先取得知识表写入互斥锁，再验证源行的实例、执行凭证、租约和准备前的数据修订号。整批插入、更新、删除及完成标记一并提交或回滚。锁等待限制 2 秒，事务内空闲限制 3 秒；模型调用不持有这些锁。发布期间仍允许普通查询，但命中计数及其他知识写入会短暂等待。

执行实例退出后，其他实例可以在租约过期后接管，状态查询将未接管的过期执行显示为 INTERRUPTED。暂停后恢复的旧执行不能提交，也不能清除新执行的租约或完成标记。尚未发布的向量保存在执行进程内，故障接管可能重新计算，不能保证故障期间供应商只收费一次。

## 源文件与人工编辑

- 已经完成过的同一文件指纹在自动启动时保持现有数据库内容，包括之后的人工编辑。
- 第一次升级启用本机制时，若已有源的片段键、标题或正文与文件不同，自动初始化会停下等待管理员确认，不覆盖已有修改。
- 文件内容、源版本或向量配置改变时，自动初始化等待管理员明确重建，防止混合版本实例反复覆盖。源版本字符串没有可靠的全序，系统不猜测哪个部署版本更新。
- 管理员 `POST /api/knowledge/reindex` 或现有管理入口明确触发同步，表示以该实例携带的文件为准：它会恢复该 source 的片段，更新变化内容，并删除该 source 中不属于文件的片段。操作前需核对人工修改；其他 source 不被替换。
- 准备期间发生人工编辑或向量重建激活时，修订号改变，旧计划拒绝提交；后台停止自动覆盖尝试，管理员检查后可重新发起同步。

`GET /api/knowledge/sync/status` 仅管理员可见，展示源、修订号、指纹、租约、完成时间、最后错误及有效状态，不返回执行凭证。BUSY 是运行竞争；REVIEW_REQUIRED 表示等待确认；EDITED 表示准备期间发生内容变更。现有 `mealcheck_knowledge_index_runs_total{outcome="deferred"}` 区分等待与失败。

完成指纹标记最近应用的源文件，并不表示数据库没有之后的人工编辑。不同部署版本被拒绝自动同步时，通过该实例的启动日志或调用返回值说明原因，仍保留当前已发布索引。

## 升级和验证

所有写入实例应先统一升级到包含 V36 的版本。旧实例没有此协调机制，不能依靠新版租约约束旧版同步器。V34、V35 是本次改动前已有的迁移，本次未修改它们。

本轮使用独立构建快照，避免其他工作对共享 `backend/target` 的影响。复现入口：

```powershell
mvn -f backend/pom.xml --batch-mode --no-transfer-progress verify -Pintegration
python deploy/scripts/verify_knowledge_cluster.py --output deploy/release-results/your-new-knowledge-run
```

脚本也支持 `--jar <固定 JAR 路径>`。它启动两个真实后端及本地向量替身，只操作随机且原先不存在的专用 Compose 项目，并在结束时清理容器和卷。生产 `.env` 不参与验收，不使用真实模型密钥。验证包含 100 条知识只计算一份向量、重启跳过、人工编辑保留、明确重建、暂停恢复、杀死后接管和无重复键日志。

第 6、7 项固定证据目录保持不变。本次源码与验收另存，不代表已经部署生产环境。
