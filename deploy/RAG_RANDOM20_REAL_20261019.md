# RAG 随机 20 题真实完整测试（2026-10-19）

20 题均完成真实问答及评分。当前最大问题是 **知识题漏检索**：19 道知识题只有 3 道调用了知识检索；库外法律题反而调用了饮食检索。检索被调用也不能保证回答有据，三道已调用题的回答都没有通过本轮严格的证据与引用复核。

## 范围与口径

- 用户明确授权仅运行这 20 道真实测试。种子 `20261019`，从 158 题中无放回随机抽取，保留原题号：25、33、36、37、39、57、61、65、76、91、97、101、102、121、122、128、129、133、134、154。含 19 道知识题、1 道库外题。
- 向量模型 `qwen3.7-text-embedding-flash`，512 维；生成与评分模型均为 `qwen3.7-flash`，思考关闭，输出上限 1600 tokens。**同模型复核不是独立人工准确率。**
- 使用隔离 PostgreSQL/pgvector 测试库，载入全部 200 条知识；精确匹配请求指纹的历史真实向量缓存复用。没有向生产知识库写入、没有发送真实用户餐食或档案。
- 生产 Function Calling 循环、工具定义、真实知识检索、回答提示词、解析和引用绑定参与测试；用户档案、记录、会话持久化为虚拟空白数据。原问题直查与模型自主构造查询分开留证。
- 工具准确率按当前 `rag-tools-v1` 严格规则：知识题必须检索，库外题不应调用工具，参数、主题组、次数、状态等均需符合要求。分母为完成的 20 题。
- 回答复核四项为正确性、有据性、引用支持性、边界，各 0～4 分；每项至少 3 分、无标记的无依据断言、拒答符合题型、引用身份有效才能通过。知识题还须有引用，库外题须无引用。**未通过不代表整段答案全错，常见原因是缺少来源或超出来源扩写。**

## 来源一致性核对与问题定位

以下是对保存的回答、轨迹和知识正文进行的核对，不是独立人工金标准，也不引入外部资料判断健康或法律建议是否正确。

1. **知识题没有可靠的必检索约束。** 模型选择采用 `ToolChoice.AUTO`；提示词允许不必要时直接作答。这次 16 道知识题没有调用检索，直接使用模型内部知识，引用绑定因此没有候选来源。该事实有完整轨迹支持，不能通过增加知识数量解决。
2. **检索成功后仍会超出证据扩写。** 第 76 题调用了正确主题，命中并引用“植物饮品的蛋白质与钙标签”，但增加了蛋白质克数、钙含量和选择阈值。所提供的条目要求核对具体产品标签，没有给出这些具体数值。第 57 题亦将定性的做法/份量差异扩展为确定的热量差异，并断言十个属于较大份量。
3. **查询主题命中不等于意图完整保留。** 第 101 题把“怎么选怎么记”改成“营养对比 热量”，实际返回“主食结构建议”“营养标签的计量单位”“份量与餐盘估算”，漏掉更直接的馒头/花卷条目。词语规则能通过，但检索与引用仍不充分，说明现有参数检查不能完整衡量语义准确率。
4. **库外边界检查太晚。** 第 154 题用“劳动合同纠纷法律依据”搜索饮食库，工具执行成功，但这是误调用。最终回答说明了能力边界且没有展示知识引用；两层结果应分别计分。原问题直查也返回了五条饮食知识，表明检索阈值没有正确识别库外问题。
5. **回答模板附带无关趋势。** 本次输出普遍包含“本周趋势：records are insufficient”等与当前单轮知识问题无关的内容，可作为后续展示和提示词调整项。
6. **原题标题标注需要单独复查。** 第 36 题标注仅接受“食堂菜品识别与替换”，但直查第一名为“麻辣烫自选食材”；第 39 题标注仅接受“份量与餐盘估算”，直查第一名为“饥饿饱腹感的补充记录”。这两项不能直接认定真实检索失败。本轮保持原标注计分，且两题的工具漏调结论不受此影响。

后续优先处理：领域/库外分流、知识问答的检索保障、保留查询意图、回答逐项绑定证据，以及去掉无关趋势模板。回答质量评分还需逐题人工校准，尤其是不能把“来源未支持”直接等同“事实错误”。这轮不做修复后重跑，也没有测试其余 138 道题。
