# 周报任务与会话错误处理修复

## 周报统计周期

周报生成、快照保存及餐食变更失效判断统一使用任务的 `report_week` 作为周期结束日期，起始日期为结束日期减去 `days - 1`。定时派发跨天恢复时，任务的创建日期不再覆盖原统计周期。生成和保存入口对无周期字段的旧对象保留创建日期回退；数据库中的 `report_week` 为非空字段。

本次修改不自动重写已保存的历史快照，不需要新增数据库迁移。

## 周报领取与执行

- 调度器只投递有界数量的执行入口；执行线程开始工作后，每次从数据库领取一个任务。等待执行入口不占用任务租约，也不增加尝试次数。
- 本机在途执行入口数量不超过周报执行池的最大线程数。重复轮询不会累积执行入口；线程池拒绝任务时还没有领取数据库任务。
- 周报执行池默认队列容量从 20 改为 0，使用直接交接，让待处理业务任务留在 PostgreSQL 队列。显式配置非零容量仍受支持，其中等待的只是执行入口。
- 调用模型前，按任务状态、尝试次数、执行 token 和租约时效原子校验并刷新执行起点。过期、被接管或失效的任务不能开始模型调用。
- 有效租约至少为 AI 单次执行期限加 30 秒，同时保留配置的更长租约。默认执行期限 120 秒、租约 600 秒；如果租约配置为 60 秒，有效租约为 150 秒。
- 完成结果仍通过原有 token 和状态条件更新发布，保留过期任务恢复、失败重试与并发提交隔离。

## 会话接口

读取、删除及继续使用不存在、已删除或不属于当前用户的会话时，返回相同的 404 语义。正常读取与删除行为保留。资源查询显式抛出 `ResponseStatusException`，不扩大通用异常处理器的匹配范围。

## 回归验证

对应测试包括 `WeeklyReportJobWorkerTest`、`WeeklyReportJobServiceTest`、`WeeklyReportJobCompletionServiceTest`、`AssistantConversationHttpTest` 及 `WeeklyReportDatabaseIntegrationTest`。

重点覆盖跨天派发后的快照周期与失效范围、等待执行时不领取任务、重复轮询有界、拒绝投递不消耗尝试次数、过期 token 不调用模型、短租约保护、资源不存在及越权访问的 404。数据库测试使用 Testcontainers 隔离 PostgreSQL；新测试日志与报告保存至根目录 `logs/backend/`。
