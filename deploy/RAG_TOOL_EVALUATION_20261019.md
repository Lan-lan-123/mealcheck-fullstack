# 原有 158 道 RAG 题的工具调用评测

> 后续题库已扩展为 200 题（180 道知识题、20 道库外题），当前入口显示“RAG 工具评测（200 题）”。
> 扩展范围、版本及复跑命令见 [评测工具说明](../tools/evaluation/README.md#shared-200-question-rag-dataset)。
> 下文保留最初 158 题实现及当时验证的记录，不代表新题库的运行结果。

管理员进入「质量评测 → 助手评测」，点击「RAG 工具评测（158 题）」。该入口复用后台任务队列、进度、逐题轨迹、历史、人工复核和运行对比；模式为 `RAG_TOOLS`。

## 标注与规则

不另建重复题库：在 `backend/src/main/resources/knowledge/rag_eval_cases.json` 的原题上添加稳定 ID `rag-001`～`rag-158` 和 `agentEvaluation`，保留原题目、预期知识标题、类别与库外题标记。规则版本为 `rag-tools-v1`。

| 题型 | 数量 | 预期行为 |
| --- | ---: | --- |
| 知识问答 | 148 | 调用 `search_diet_knowledge`，返回 `SUCCESS`；禁止读取个人餐食、周报和目标 |
| 库外题 | 10 | 不调用任何工具；正确不调用也计为工具规则通过 |

逐题检查：漏调、禁用或额外工具、顺序、所有调用成功状态、工具名称与轨迹一致、参数格式、查询主题组、次数和重复查询。知识题最多两次查询；库外题零次。`query` 必须为非空字符串且不超过 500 字符，不能有额外参数；`limit` 为 1～5 的整数，省略或 null 时默认 3，与生产工具一致。

`queryTopicGroups` 每组包含可接受的主题词/口语表达，查询须命中每组至少一个词。它是可复现的词语覆盖检查，不能完整判定查询语义准确性。增加同义表达需要更新标注并重新运行；同一 query 和 limit 的重复调用判失败。

## 准确率口径

**工具调用准确率（规则）= 生成执行成功且全部工具规则通过的题数 ÷ 已完成题数。**

执行错误仍计入分母；完整运行的分母为 158，中途进度使用实际已完成题数。未执行的题暂不计入进度准确率。分类通过率使用同一口径。未完成或含执行错误的运行不能作为完整评测结论。

该指标是严格的逐题通过率，包含 10 道正确不调用工具的负例；不是单个 tool call 的精确率/召回率，也不是最终回答正确率。原 10/50/200 题模式的指标口径保持不变。

## 执行范围

该模式主动运行生产 Function Calling 决策循环与工具规格，使用隔离的工具执行层。知识正文仅在模型选择调用检索工具后，按原题预期标题从随代码发布的知识库返回受控样本，遵守请求条数。个人工具仅有空白合成数据，不访问真实用户资料。规则与知识正文不会作为评分答案提前透露给模型。

不调用真实向量检索接口，不测实时检索排序，不调用裁判模型，也不评意图识别、回答质量、引用支持度、拒答质量或发布条件。完成标记为「工具规则已评测」，包含错误则标记「结果不完整」。回答质量、意图及裁判在页面显示为未评测/未使用。

正式点击运行会调用已配置的生成模型并产生费用。任务保存题库与知识快照的 SHA-256 指纹；可在历史中检查逐题参数、工具状态、错误和规则失败原因。原「知识检索质量评测」继续用于 Hit@K、MRR 等检索指标。

## 本次本地验证

- 5 个后端测试类共 23 项模拟测试：涵盖全部 158 题标注、原 RAG 检索兼容性、原 200 题模式、参数/轨迹校验、隔离工具样本、错误分母以及不依赖裁判或真实向量服务。
- 前端类型检查与构建；浏览器使用模拟 API 验证提交 `RAG_TOOLS`、准确率与逐题失败展示，以及未评回答质量的标记。
- 没有调用真实模型；本地模拟通过率不能视作实际模型准确率。

日志和配套报告位于项目 `logs/backend/`、`logs/frontend/`。后端可用 `-Dmealcheck.testReportsDirectory=<logs 下本次批次目录>` 指定 Surefire 报告目录。
