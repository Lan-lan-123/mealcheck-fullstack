# RAG 工具与检索链路评测

管理员进入「质量评测 → RAG 链路评测」，点击「RAG 链路评测（200 题）」。
模式为 `RAG_CHAIN`，一次后台任务依次处理同一题的工具流程、实际知识检索和阶段判分，
统一保存进度、逐题证据、运行历史与人工复核。助手评测页提供同一流程的快捷入口。

## 实际执行流程

1. 读取共享的 200 道 RAG 题，冻结问题、工具规则、证据标注和版本。
2. 使用生产 Function Calling 流程与工具规格。轨迹区分后端保障执行与模型请求。
3. `search_diet_knowledge` 被执行时，以该调用的实际 `query`、`limit` 运行当前生效的
   向量检索、重排和过滤。结果同时返回给助手并保存为该题检索证据。
4. 工具参数、预期/禁用工具、顺序、成功状态及次数仍按已有规则检查。
   检索相关性依据实际返回正文的内容指纹、原文片段和相关性等级比较，不另发查询补测。
5. 每题工具规则和检索阶段都通过，且整题执行成功，才计为链路通过。

题目预期知识不作为工具返回样本注入，不提前告知模型。检索复用生产查询的候选召回、
重排和过滤实现；评测绕过查询缓存、不写入用户检索统计或知识命中次数，个人工具禁止执行。
向量模式与重排是否启用取决于当前配置；使用本地哈希向量不能解释为真实语义能力验证。

## 阶段状态与分母

| 检索状态 | 含义 |
| --- | --- |
| PASSED | 全部成功检索的实际结果累计覆盖必需的直接证据组；允许补充检索找齐证据 |
| FAILED | 成功检索后仍未覆盖必需证据（含空结果），或库外题错误触发检索 |
| NOT_CALLED | 知识题没有执行检索，不把它伪装成一次空结果查询 |
| NOT_REQUIRED | 库外题未执行检索，配合工具检查和整题执行状态判断边界处理 |
| ERROR | 实际检索调用失败；错误类型与实际查询保留在逐题证据中 |

检索后模型回答失败时，整题为 ERROR，但已成功执行的检索证据和阶段结果继续保留。
上游工具流程失败导致没有检索时，检索阶段保持 NOT_CALLED，不捏造检索错误。

- 链路通过率：工具和检索均通过且执行成功的题数 / 已完成题数，执行错误计入分母。
- 工具通过率：保持原有规则口径，独立展示，不因检索漏召回而把正确工具判错。
- 首轮 Hit@3/5、MRR、nDCG@5：以首次检索成功返回的知识题为分母；空结果计未命中。
  未调用与实际检索错误单列。这些条件指标不能单独当作整条链路的成功率。
- 最终证据覆盖率：最终已覆盖全部必需证据组的知识题 / 已完成且含新版判分信息的知识题。
  未调用和执行错误仍计入分母。先获得证据再发生模型错误，可以保留覆盖结果，但整题不能通过。
- 补充检索修复数：首轮证据未齐、后续检索补齐且执行无错误的题数；不消除首轮漏召回。
- 库外题正确不调用：排除执行错误后，同时满足工具检查和 NOT_REQUIRED 的库外题 / 已完成库外题。
- 补充查询：全部保存；用于最终覆盖，不替换首次查询的排序结果。

逐题 `ragChain` 保存预期证据、标注状态、最终覆盖、补充修复、阶段状态、排名指标及每次调用的 ID、查询、请求条数、
耗时、结果 ID/标题/类别/分数、内容指纹、实际正文和错误类型。历史 JSON 可以完整回读；新旧模式有不同的
模式标识、版本和指纹，不能直接比较绝对通过率。运行对比也能识别两次均通过但排名或检索证据变化的题目。

## 证据标注与题目边界

当前 `rag-200-v4+rag-tools-v2` 共 200 题：168 道可回答题、12 道域内证据不足题、20 道库外题。
2026-10-20 正文去套话后，原引文已重新绑定到 v7 实际片段；问题、工具规则与评分公式不变。
新增正文相关性仍待独立复核，不能把原锚点迁移等同于全部新说明已完成标注。
本版实际每主题 1 片，原长度分档未满足。详见 `KNOWLEDGE_TOPIC_REWRITE_20261020.md`。
前两类均要求知识检索；域内证据不足题测试缺少重量、标签、配料等信息时，能否取得解释边界所需的知识。
这 12 题的检索通过不代表最终回答已正确承认信息不足，回答仍需复核。

180 道知识题都绑定生产 Markdown 分块的内容指纹与原文片段。等级 2 为直接证据，等级 1 为相关背景；
背景可以贡献首轮排序指标，但不能满足直接证据组。22 题允许多个直接来源作为替代证据。
最终覆盖按证据组计算，每组命中一个允许来源即可。首轮 nDCG@5 使用分级增益 `(2^等级-1)` 与理想排序归一化，
同一来源重复返回只计一次。相同标题、不同正文不能冒充已标注来源。

所有新标注均明确为 `PENDING_HUMAN_REVIEW`，`independentlyAnnotated=false`。
它们是根据原有目标和当前正文编写、细化的规则标注；内容指纹和原文校验只证明来源一致，不能证明语义标注正确。
知识正文变化后应检查语料与标注版本，不能直接把指纹失配归因于模型退化。
20 道固定回归题和 180 道扩展池均已用于本地开发测试，目前没有独立采集的外部盲测题。

可导出不包含逐题建议标签的空白复核包：

```powershell
python tools/run_logged.py --group backend --name rag-independent-review -- python tools/evaluation/export_rag_review.py
```

输出位于新建的 `logs/backend/rag-independent-review-时间戳/`，包含完整语料、200 道空白复核记录和来源指纹。
应由未参与出题、调试的人独立审核；生成空白文件不等于完成人工复核，也不构成外部盲测。

链路判分版本为 `rag-chain-v2`。历史记录保留原判分，旧记录不补造最终覆盖指标；排队中的旧版本任务会拒绝套用新规则，需重新提交。
单独检索诊断仍使用标题代理指标，不能与新版正文证据覆盖率混为同一口径。

## 回答质量与运行边界

本模式自动评估工具和检索，不提供最终回答质量分，也不要求配置独立评分裁判。
助手仍走生产回答及证据约束流程，其中的回答生成、修复与一致性复核可能继续调用生成模型。
真实运行还可能产生向量和重排费用，页面沿用启动确认。修改代码与本地自动测试不触发真实供应商请求。

原 `RAG_TOOLS` 受控工具模式继续兼容历史和 API；单独检索诊断收进链路页的可选折叠区，
用于排查召回与过滤，不被计入上方链路运行。原助手 QUICK / STANDARD / FULL 模式保持原有含义。

## 本地验证

新增 `RagChainExecutionTest` 与 `RagChainAssessmentTest` 验证真实生产编排如何连接到检索组件，
包括一次调用对应一次检索、空结果、库外题不调用、检索错误、后续模型错误、个人工具隔离、
参数校验、首次与补充查询分离。`RagEvidenceLabelsTest` 另验证正文绑定、标注完整性、分级排序、替代来源、
多组覆盖、重复结果及错误不能被覆盖结果掩盖。测试使用模型与向量服务替身，不衡量实际模型质量。

`AssistantBenchmarkServiceTest` 运行整套 200 题的受控测试，分别检查工具失败、检索未命中、
未执行、执行错误、通过率分母和历史 JSON 往返。管理端浏览器测试验证一次提交、独立阶段指标、
逐题真实查询及结果展示，类型检查与构建验证前端兼容性。所有日志、截图和报告保存在项目 `logs/`。
