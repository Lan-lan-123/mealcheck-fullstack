# 查询构造与引用绑定：代码变更

本轮按用户要求只实现这两项，不运行测试、不调用模型，不重新生成知识向量，也未更新运行中的服务。

## 查询构造

- 普通问答使用原问题或已消解指代的追问，不再拼接意图词和技能词。
- 追问只补充当前对话主题；完整历史摘要继续供回答提示词使用，不再混入检索查询。
- 工具调用提示词同样要求保留具体问题，禁止因为技能选择而追加宽泛饮食词。

## 引用绑定

- 提供给模型的知识包含服务端真实 ID。
- 普通问答与工具调用模型输出新增内部字段 `referenceIds`、`refused`。前端响应结构保持原样，由后端组装 `references`。
- 仅接受本次候选中存在的正整数 ID，去重、按模型选择顺序保留，最多 3 条。候选池不再预先截取前三条，因此排在第 4、5 位的知识也可以被模型选择。
- `refused=true`、引用元数据缺失/格式无效或 ID 不属于本次候选时，不自动补候选引用。缺少明确的 `refused=false` 也不生成引用。
- 本地模板降级不再声称“参考了第一条知识”，不附带没有建立依据关系的引用。解析普通模型回答时，也不再额外补入本地模板建议。
- 流式回答保留自然语言逐段输出；模型在结尾给出内部引用元数据，服务端过滤标签和元数据，仅将正文传给前端，再组装校验后的引用。协议缺失或损坏时保留正文、引用留空。

合法 ID 校验只能约束来源身份，不能证明每项断言都得到知识正文支持。独立的数值依据校验、库外意图识别和检索阈值优化不包含在本轮。
