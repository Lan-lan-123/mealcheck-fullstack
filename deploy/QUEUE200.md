# 200 张未完成任务容量

2026-10-16：全站未完成图片任务默认上限由 64 提高到 200。它包含上传预处理占位、排队、执行以及过期待接管任务，不是额外增加 200 个排队名额。每用户仍最多 2 张。普通/生产 Compose、应用默认和兼容覆盖文件一致。

上传入口保持 64，图片解码仍为 2 个执行、62 个等待、最多等 15 秒；消费者保持 40，RabbitMQ prefetch 为 1。全站 AI 并发许可 42、滚动分钟 120 次准入、400 毫秒最小启动间隔保持不变。200 张是可累积的未完成任务容量，不承诺 200 个同时上传请求都首次接受，更不代表一分钟完成 200 张。

## 状态与恢复

接口继续保留 PENDING/PROCESSING/SUCCEEDED/FAILED/RETRYABLE，新增 stage 和安全 message：

| stage | 含义 |
| --- | --- |
| ACCEPTED | 请求占位已接受，图片仍在校验；不是已完成持久化入队 |
| QUEUED | 图片已持久化、正在排队；或执行租约到期等待自动恢复 |
| PROCESSING | 消费者已领取，正在执行（可能等待 AI 调用许可） |
| COMPLETED | 结果与餐食记录已保存 |
| FAILED | 失败或上传占位到期需要用户处理 |

前端显示上传、已接收、排队中、处理中、完成，支持刷新后查询原任务；不虚构精确排队位置和完成时间。执行租约到期且图片仍在的任务返回 PENDING/QUEUED，不再过早显示重传失败。只有未持久化图片的过期占位返回 RETRYABLE。

消息为任务 UUID，图片仍保存在 PostgreSQL input_image，完成后转存本地图片卷并清空暂存 payload。没有启用 OSS。任务和 Outbox 在同一事务持久化，发布使用确认机制，确认后的正常积压不会定时重复发布；过期执行租约可被重新调度，旧 token 无法提交结果。

## 存储保护与检查

新增 MEALCHECK_ANALYSIS_MAX_STORED_IMAGE_BYTES，默认 536870912（512 MiB）。写入图片 payload 时在同一个数据库全局事务锁下统计全部暂存图片，包括失败后留存的 payload；同键替换不重复计算。超过返回 429 ANALYSIS_STORAGE_BUSY，不写入新 payload 或 Outbox，前端提示等待后用原图、原请求重试。数据库出错不会绕过保护。

任务数量和字节上限必须同时满足。例如 200 张每张 250 KiB 约 49 MiB；若每张归一化后接近 10 MiB，字节上限会先触发，不能承诺接受 200 张最大图片。失败图片按既有 7 天保留策略清理；大量失败占满字节预算时，应排查并通过既有管理/清理流程释放，不能仅继续提高数量。

512 MiB 仅是图片 payload 逻辑预算，不包括 WAL、MVCC、索引、备份、历史餐食图片。上传临时文件预算保持 1 GiB；它与持久化队列分别计算，预留和已落盘文件按保守规则检查，磁盘不足时提前拒绝。

部署前运行只读检查（选用实际项目名、Compose 文件和环境文件）：

```powershell
python deploy/scripts/check_queue_capacity.py --project-name mealcheck
python deploy/scripts/check_queue_capacity.py -f docker-compose.prod.yml --env-file .env.production --project-name mealcheck
```

脚本只输出容量、数据库大小、图片字节总量及对应容器文件系统空闲空间，不输出凭据。数据库空闲建议至少 max(2 GiB, 4 倍 payload 预算)，上传临时目录至少 1 GiB 加 64 MiB 余量，结果图片目录至少留出 payload 预算大小。这是预检，不预留磁盘；共享同一底层文件系统时还要合计同时增长量。返回失败应先释放/扩展存储，不能据容器启动判断容量充足。

## 应用与回退

现有环境变量覆盖默认值。更新源码后重建后端并重新创建容器，检查实际 MEALCHECK_ANALYSIS_MAX_OUTSTANDING=200、每用户 2、字节预算 512 MiB；只重启旧容器不会应用。正常生产升级应保留数据库及上传卷，并沿用备份流程。

回退可显式设置 MEALCHECK_ANALYSIS_MAX_OUTSTANDING=64；若已有超过 64 张，保留并继续处理已有任务，直到低于上限才接收新任务。不得为回退清空队列或删除数据卷。

本次模型使用测试替身进行积压/恢复验收，不消耗真实 Max token。之前 50 张 56.47 秒是历史独立实测，不可解释为 200 张完整真实 API 验收。
