# 前端加载、记录查询与缓存一致性优化（2026-10-14）

## 行为

- 登录入口按需加载用户和管理工作区，提供加载提示。工作区渲染或动态模块加载失败时显示重新加载入口。
- `usePageResource` 将 AbortSignal 传给读取接口；切换页面、筛选、失效或替换数据时取消旧请求，同时保留旧结果隔离。行为目标和行动计划的列表读取也支持取消。取消浏览器请求不保证已开始的数据库查询停止。
- 用户记录页读取摘要；打开详情、编辑用餐信息或纠错时再读取完整记录。加载详情期间可以关闭，关闭后不会迟到打开弹窗。
- 通用按钮使用项目绿色、9px 圆角、悬停和键盘焦点状态；移动端操作按钮至少 44px 高。补记、纠错、分页、计划、反馈及任务恢复入口显式采用共享按钮类。主操作和危险操作保留各自语义。
- 弹窗关闭按钮不再占满移动端标题栏；弹窗显示期间锁住背景滚动，层级高于助手入口，关闭后恢复滚动和焦点。

## 接口与兼容性

- 新增 `GET /api/meals/summaries`，参数与既有用户分页接口一致：page、size、goal、from、to、minScore、maxScore。返回 content、totalElements、totalPages、page、size。
- 摘要仅包含 ID、用餐/创建时间、餐次、记录来源、时间确认状态、目标、评分、简述和最多六个食物名称。按实际用餐时间及 ID 降序排列，结束日期使用次日开始的排他边界。
- 新增 `GET /api/meals/{id}` 获取完整记录。认证用户只能访问自己的记录；不存在或属于其他用户时返回 404。
- 原 `/api/meals` 完整列表和周报期间列表保持原响应，既有外部客户端可继续使用。
- 管理列表仍使用原页码与总数接口；此次未切换游标交互。

## 知识库缓存

V32 新增 `knowledge_cache_state` 和数据库触发器。知识插入、删除、检索相关列更新及 TRUNCATE 与缓存版本号在同一个事务内提交或回滚。命中次数和最后命中时间更新不推进版本。

每次搜索从数据库取得共享版本，将新鲜缓存、旧值缓存与加载合并键置于该版本的命名空间。旧搜索即使在修改完成后写回，也只写入旧命名空间；其他实例读取新版本后不会采用它。旧命名空间仍有既有 TTL，缓存清理接口保留。

此机制每次搜索增加一次小型版本查询；知识修改期间会更新一个共享版本行。它解决缓存失效竞态，不代表助手任务注册已支持多个实例。

## 验证与边界

- 后端离线单元/HTTP 回归：276 项通过，零失败、错误或跳过。日志：`backend/target/frontend-backend-optimization-unit.log`。
- 新增缓存并发回归：两个服务实例共享缓存，旧查询延迟完成后仍不能污染新版本结果。
- 新增 HTTP 回归：摘要使用认证用户身份，完整详情不会泄露其他用户记录。
- 前端单元测试 33 项、浏览器回归 72 项全部通过；浏览器回归覆盖请求取消、摘要与详情分离、懒加载失败恢复、移动按钮样式和焦点。最终结果见 `logs/frontend/optimization-e2e.log`。
- 生产入口 JS：215.18 KB，gzip 68.30 KB；优化前为 412.33 KB，gzip 121.82 KB。这是构建体积，不是实际首屏延迟测量。
- 补充了 PostgreSQL 集成测试，覆盖摘要查询、实际用餐日期、六个名称上限、无实体加载、V32 版本提交/回滚及命中统计不失效。
- 首轮 Docker Desktop 因运行时套接字启动失败，数据库集成测试当时未运行。后续已保留失效运行时目录并恢复 Docker，完成真实数据库验证，并修复触发器阻止向量类型切换的问题。最新结果见 [工程优化验证](FRONTEND_ENGINEERING_VERIFICATION.md)。

Docker 恢复后可运行：

```powershell
Set-Location E:/mealcheck-fullstack/backend
mvn --batch-mode --no-transfer-progress verify -Pintegration
```

本轮没有发布或重建运行中的业务容器。更新后端时需执行新增 V32 迁移，并与使用新摘要接口的前端一同更新。
