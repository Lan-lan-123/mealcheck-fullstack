# 当前版本真实端到端验收（2026-10-15）

最终一轮 **10/10 个浏览器场景通过**。从页面注册、登录和上传开始，真实经过 Nginx、后端、Redis、PostgreSQL、RabbitMQ 和阿里云百炼 `qwen3.8-max`，完成识别、保存、展示、刷新恢复、助手及周报流程。浏览器没有拦截或伪造 API 响应，模型没有使用替身。

数据库自动完成 V1～V32 迁移；知识库实际导入 100 个片段。本轮使用真实数据库检索，周报检索到 5 条证据。未配置外部 embedding/rerank，因此没有验证这些外部服务。

## 本次修复及保留的问题

**已修复：新账号空目标兼容。** 后端 `/api/profile/goals/current` 在未设置目标时返回空值，前端此前强制要求对象，导致页面显示“服务返回的数据格式异常”。现在仅允许 GET 返回空值，PUT 保存结果仍要求合法对象，并同步修正返回类型。新增回归测试通过实际 HTTP 空响应验证此契约，同时保持非法对象和 PUT 空值拒绝。最终浏览器复测验证新账号无错误横幅。

改动位置：[validation.js](E:/mealcheck-fullstack/frontend/src/api/validation.js)、[client.js](E:/mealcheck-fullstack/frontend/src/api/client.js)、[回归测试](E:/mealcheck-fullstack/frontend/test/apiValidation.test.js)。

**待优化：图片请求的预留费用偏高。** 初次将隔离环境费用上限设为 2 元，上传在模型请求前即被拒绝，用量为 0。代码使用整个请求字符串长度预估输入量，把图片 Base64 一并按文本估算，导致预留明显高于实际费用。为了继续验证链路，仅把本次隔离环境预留上限改为 50 元，同时保留 30 次真实调用总上限。最终实际结算仅 0.37 元，预留完全释放。现有业务配置及生产计费逻辑未修改；低金额预算下图片上传可能提前被拒绝，这一问题仍需单独优化，不能把本轮通过解读为该估算问题已修复。

执行过程中还保留了两次测试准备中断：一次在后端重建尚未就绪时访问得到 502，没有模型调用；另一次助手已实际完成，但脚本错误地要求空输入框的发送按钮可用。已改为检查完成消息、反馈入口及持久化状态。它们的记录和先前发现页面问题的截图均保留，没有把失败尝试移出费用统计。
