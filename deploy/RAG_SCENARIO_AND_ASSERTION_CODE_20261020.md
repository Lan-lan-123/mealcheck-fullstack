# 场景召回与逐分句核验代码改进（2026-10-20）

按用户要求，本次仅修改代码并做人工阅读、差异及空白格式检查。**未编译、未运行单元或集成测试、未运行评测、未调用真实模型。** 以前的65%/80%代理通过率属于旧版本，不能作为本次修改后的效果。

## 场景召回与来源排序

现有系统已有向量、整句标题和正文相似度的RRF融合，本次在其上增加独立的短词候选通道，没有替换向量模型或修改已有知识正文。

- 新增 `KnowledgeQueryFocus`：生成最多32个中文2～4字短词、短独立汉字及英文/数字特征，跳过部分提问套话，并分配句首、句尾及不同文本片段的特征名额。属于通用词法特征，不是针对特定题号或完整问句的特殊分支。
- `PgVectorKnowledgeService.search` 新增独立关键词候选池：标题命中权重高于正文，按全库命中文档频率计算稀有度，再与原有通道做RRF融合。各通道候选上限100；焦点通道使用现有关键词权重的一半，其余分给整句标题和正文。无焦点特征时保留原有关键词分配。
- `KnowledgeRerankerService` 在远程重排成功、未配置和远程失败回退三种路径均做本地场景排序。采用原排序80%、焦点排序20%的秩比调整，保留原分数的量级，避免把低分候选仅因局部排名提高就提升为高分。
- 远程重排先保留完整候选再做本地场景排序，最后取limit。
- 搜索缓存签名加入检索版本、权重及候选参数；本地重排版本和RRF参数也进入签名，防止继续复用旧排序缓存。

此改动旨在增加“具体对象、动作或条件中的短词”进入候选的机会。词法命中和排序分数不构成证据充分性的证明，后续仍需语义核验。

## 有上限的补充检索

`AssistantFunctionCallingService` 为每个知识请求建立共享预算，模型提出的补查与后端审核触发的补查合计最多执行一次，并受既有总工具调用上限和原请求截止时间约束。

- 原问检索无结果时，可以用原问与短词特征补查一次。
- 审核明确报告核心证据缺口，或核心ANSWER的场景条件不成立且无法交付时，可以补查一次。
- 审核缺字段、分句ID不完整或重复等结构问题不会直接触发补查，而是进入有界改写。
- 补查保留完整原问，并追加精简焦点词；不允许用改写替代原始意图。
- 按ID合并来源，保留原始候选优先顺序，不用新检索覆盖原来源。
- 补查预算用完后不再给模型开放知识工具。模型再次请求补查记录SKIPPED并获得使用已有证据的反馈，不伪装成成功执行。
- 所有真实补查记录参数、状态、耗时及MODEL/ORCHESTRATOR来源。模型工具参数仍先校验，不通过未知字段或错误类型参数。
- 补查失败不丢弃已核验内容；生成仍最多增加一次改写，语义审核最多两次。若后续失败，保留之前已审核的可用回答；完全没有可用内容时继续安全兜底。

## 逐分句完整覆盖

新增 `AssistantClaimCoverage`，将claim文本划为确定的原文字符区间，附稳定分句ID；标点及常见因果、转折连接词形成边界。分句仍携带完整claim上下文，避免脱离语境判断。

内部核验协议升级为 `assertion-coverage-v2`：

1. 每个claim及其所有分句ID都必须有审核结果，未知ID、缺失或重复覆盖不能按通过处理。
2. 每个分句分别返回事实、程度/比较/确定性、因果、对象/场景/前提四项布尔检查，以及实际使用的evidenceIds。
3. evidenceIds只允许指向该claim已校验的原文绑定，不能借用别的claim或猜测来源。数值单位再对该分句实际选中的引文复查。
4. 增加保守的强度锚点检查；如原文没有相应强度或比较线索，“差异很大”“一定”“更健康”等表述不能仅凭审核器给true放行。该启发式可能偏保守，并不替代语义判断。
5. 全部支持时保留完整claim；部分不支持时，仅保留后端和审核器均确认可以独立展示的原文分句，重新计算所用来源。
6. 条件、指代或因果依赖不能通过裁掉前提变成无条件建议。含条件/让步结构的复合claim采用保守处理。

每条claim最多8个分句，整个回答最多12个分句，reason要求简短，以限制核验输出规模。整体旧式 `supported=true` 不再作为完整分句覆盖的替代。

部分内容被删减时仍标记partial并说明未知；没有可回应原问题的ANSWER时，不以建议或来源相关性冒充有效回答。
