## 发现的问题

### 同时缺输入与知识，被误判为只缺输入

问题要求判断某食品是否符合当前冷藏条件，并解释保存温度核对原则。用户没有提供标签要求和实际温度；唯一来源只有“请记录食品名称。”，也缺少核对原则。

预期为 `MISSING_BOTH`。实际返回：

```json
{
  "informationStatus": "MISSING_INPUT",
  "missingInformation": ["用户输入：实际冷藏温度", "用户输入：食品标签保存要求"],
  "answersQuestion": false,
  "needsMoreEvidence": false
}
```

模型正确识别了用户事实缺口，也意识到候选回答未回应问题，但漏掉了知识缺口。后端未放行该回答；不过按现有编排，`needsMoreEvidence=false` 也不会触发审核要求的知识补检。这一例直接测的是生产复核组件，没有实际执行检索或完整业务 HTTP 请求。

建议优先把“用户事实是否足够”和“核心解释的来源是否足够”拆成两个独立判断，再映射四种状态；不要让已识别到的用户缺项遮住知识缺项。修复后应保留本例，并增加不同主题的对照案例，重新验证真实分类与补检行为。

证据：新增批次的 `missing-both-result.json`，其中保留调用前预期、完整实际审核和本地拦截结果。

### 因果词规则误删合理的信息边界解释

原有用油量题中，模型生成了“照片……不能可靠提供……调味油……，因此无法根据照片确定沙拉酱里用了多少油。”。审核模型认为最后的结论由前文限制支持，四项检查均通过。

本地 `AssistantClaimCoverage.strengthGap` 把“因此”作为因果词；绑定来源没有对应的肯定因果词，因此将该分句标为 `UNSUPPORTED_STRENGTH` 并删除。这里讨论的是信息不足所导出的认识限制，并非把相关性推成食物造成健康变化。

最终仍保留“不能可靠提供……调味油”等核心解释，没有编造油量，分类为 `MISSING_INPUT`、`partial=true`，实际固定读取只有一次。因此原问答自动验收通过，但人工核对原始生成、语义审核和最终回答后，仍应把这一误删记录为改进点。

建议调整因果规则的适用范围，区分经验因果结论与信息不足解释；不能简单移除因果检查。此项本轮尚未修复。

证据：原问答批次的 `04-response.json`（生成）、`05-response.json`（审核）与 `rag-172-result.json`（最终回答和 `groundingIssues`）。

## 生产问答与识图的具体边界

- 便利店题本次执行了两次固定知识读取：一次编排初始读取、一次模型带焦点词的可选查询；不能表述为该题完全没有额外读取。最终 `SUFFICIENT`、缺项列表为空。固定来源在两次读取中相同，未测新增证据的实际召回收益。
- 用油题执行一次固定读取，分类与“不编造实际用量”的要求正确。引用存在性通过并不表示所有语义和表达细节都已由这两题证明。
- 六张图在运行前已视觉检查并记录 SHA。`synth-003` 和 `synth-083` 虽然原数据标签含 occlusion，实际只是附近有餐具，不能充作严重遮挡样本。
- 饮料图实际输出“冰可乐”、置信度 0.95，该饮品的油炸与高油属性保持未知；本轮基础断言检查饮品被识别，没有验证特定配方或含糖量。食物名称准确率和置信度校准不能由 6/6 基础通过推出。
- 仍未覆盖少量可食剩菜、严重遮挡、可读/不可读包装标签、不透明杯内未知饮品等图片。没有用不存在的图像或仅由提示描述构造的响应冒充真实识图测试。
- 这些是助手编写的固定合成案例，不是独立人工金标或留出集；单轮结果不能估计总体准确率。完整向量召回链路仍未评测，输入已补齐的真实多轮历史与真实补检后的四分类转换也未由本轮直接验证。
