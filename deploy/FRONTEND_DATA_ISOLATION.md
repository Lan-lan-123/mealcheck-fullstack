# 前端页面数据拆分验收（2026-10-02）

用户工作台从 `main.jsx` 独立为 `UserWorkspacePage.jsx`，饮食记录与目标表单各有独立组件。管理员的用户、餐食、知识库、异常上传和审计列表也已独立为组件，共用表格、分页和图表展示组件。

`usePageResource` 为每个数据资源分别管理请求版本、缓存、加载状态和错误。只有当前页面需要的数据才会请求；快速切换筛选或页面时，旧响应不能覆盖新页面。缓存最多保留 20 个查询组合，重新进入页面时检查 30 秒有效期，也可通过页头刷新或错误提示中的重试按钮主动刷新。

| 页面 | 自动请求的数据 |
| --- | --- |
| 用户饮食分析、饮食目标 | 当前目标 |
| 用户饮食记录 | 当前页记录与当前筛选条件 |
| 用户饮食趋势 | 趋势 |
| 用户周报 | 最新周报；生成期间暂停最新周报查询 |
| 管理员概览、监控 | 概览与健康状态 |
| 管理员助手统计 | 概览中的助手统计 |
| 管理员用户、知识库、异常上传、审计 | 对应列表 |
| 管理员餐食 | 餐食列表与统计，各自更新、各自处理错误 |

管理员的新增、编辑、删除操作只使相关资源失效。当前可见的相关资源立即刷新，隐藏页面等重新打开时再请求。后台操作的加载、错误和通知状态也按页面保存。助手评测的状态、历史与候选样本分别更新，单个请求失败不阻止其他成功结果展示。

用户新增分析、识别纠错、删除记录会使记录、趋势和周报更新；目标表单不受影响。目标草稿在首次请求尚未返回时即可编辑，迟到响应不会覆盖编辑内容。保存目标后更新目标缓存，保存过程中继续输入的新草稿也会保留。分析、删除记录和保存目标分别管理忙碌状态。

浏览器回归覆盖可见页面请求数量、分页请求隔离、知识库失败与重试、统计失败时的餐食列表展示、记录筛选及分页保留目标草稿、迟到目标响应、目标保存的刷新范围，以及保存途中继续编辑和切换到图片分析。原有登录、上传、纠错、周报、删除、请求顺序和移动端布局测试继续保留。

浏览器测试使用确定性 API 夹具，用于验证前端交互和请求行为；真实服务的模型质量与生产容量须分别验收。

本轮验证通过：12 个前端单元测试、23 个浏览器回归测试及生产构建。浏览器回归使用本机 Chrome 执行，包含桌面、平板与移动端布局。
