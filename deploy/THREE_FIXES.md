# 图片加载、评测任务与时间一致性

## 图片

`AuthImage` 取消切换或卸载时的请求，并独立检查请求是否仍有效。读取 Blob 后再次检查有效性；替换、卸载和图片解码失败时释放对象 URL。无图片、加载中和加载失败为不同状态，失败可以手动重试。

## 助手评测任务

V24 新建 `assistant_evaluation_tasks`。数据库事务、全站活动任务唯一索引和提交锁保证只有一个 PENDING/RUNNING 任务；重复提交返回活动任务。任何实例可以领取未开始的任务，执行令牌保护进度和终态写入。默认执行租约 90 秒、独立心跳 10 秒。每条用例及每次物理模型调用前验证执行权，工具执行线程继承该检查。

当前状态由数据库读取。前端按 runId 查询该次运行的历史详情，等待执行和执行中均持续轮询；离开页面取消请求。

运行任务租约过期后，保留已完成结果，标为 FAILED/INCOMPLETE。管理员显式重新运行，系统不自动重放已开始的评测，以避免增加模型费用。已经发送的远程请求不能承诺在租约丢失时被供应商取消。未领取的任务能够被新实例接管。执行器拒绝且尚未执行时退回 PENDING，新的领取使用新令牌。

任务保存提交时的完整用例、rubric 和数据集标识；工作实例的生成/裁判模型名称必须匹配任务。模型温度、工具实现等其余运行配置仍应在部署层保持一致。

升级须先停止旧版评测工作实例，再应用 V24 和启动新版实例。旧版没有执行令牌，不能与新版混合执行。迁移将原 RUNNING 历史标为 INCOMPLETE，保留原结果。不会恢复或重放这些旧运行。

## 时间协议与历史兼容

保留已有 PostgreSQL TIMESTAMP 字段，避免在未确定来源时对历史数据进行批量平移。通过 `MEALCHECK_TIMESTAMP_STORAGE_ZONE` 明确这些字段的含义，默认 UTC，沿用容器部署及原有趋势查询的 UTC 约定。应用启动时设置同一 JVM 时区，数据库连接和 Hibernate 使用同一存储时区；业务代码通过 AppTime 明确取得当前时间。

API 的 LocalDateTime 时间点统一输出带偏移的 ISO 8601。反序列化兼容旧字符串/数组快照及新偏移时间，并转换回存储时区的 LocalDateTime。新增评测任务租约使用 TIMESTAMPTZ 与数据库 clock_timestamp，不受应用主机时间漂移影响。

`MEALCHECK_BUSINESS_ZONE` 默认 Asia/Shanghai，控制餐食日期筛选、趋势分组、管理端按日统计、主动建议、周报日期及周报定时触发。日期区间采用业务时区零点到下一天零点的半开区间，再转换为存储时区查询。业务日期字段仍为日期，不附加时区。

前端统一使用 formatTime，以 `VITE_BUSINESS_ZONE`（默认 Asia/Shanghai）展示时间点。无偏移的旧响应默认按 UTC 解释，可用 `VITE_LEGACY_TIMESTAMP_OFFSET`（默认 Z）显式指定原偏移。生产 Compose 传入前端构建参数，修改这些前端参数后需重建前端。

如果既有数据库来自北京时间的本机运行，应先用已知事件/日志核对，确认同一数据库全部值的含义后，将存储时区设为 Asia/Shanghai，旧前端响应偏移设为 +08:00；不要直接给原值贴 UTC 标签。存在混合来源时，必须先完成按来源审计，不能用单个配置修复全部历史。此次修复不宣称已审计真实生产历史，也不迁移其时间值。

本次只读核对的现有容量环境：后端系统时区为 `UTC +0000`，PostgreSQL 会话时区为 `Etc/UTC`。这支持该环境继续使用 UTC 默认值，不能推断其他部署或更早的本机数据也是 UTC。

## 验证

前端：`npm test`、`npm run build`、`npm run test:e2e`。新增图片延迟响应、Blob 解码期间卸载、失败重试、解码失败及跨浏览器时区测试。

后端：`mvn verify -Pintegration`。新增双实例并发接单/领取、统一进度、租约过期/迟到结果、执行器拒绝后领取、模型调用前租约校验，以及北京时间午夜的查询和分组测试。集成测试使用独立 Testcontainers 数据库，不操作现有业务容器，不调用真实模型。

本次工作区验收：后端全量单元测试 225 项、全量数据库集成测试 64 项均通过；前端单元测试 22 项、浏览器回归 45 项均通过，生产构建通过。最后补充的失败任务筛选时间解析通过 11 项专项后端测试；页面时间标签更新后，4 项相关浏览器测试再次通过。

证据：`backend/target/three-fixes-final-unit.log`、`backend/target/three-fixes-verification.log`、`backend/target/time-filter-verification.log`、`frontend/three-fixes-e2e.log`、`frontend/time-filter-e2e.log`。沙箱内首次 Java 测试受 loopback 权限限制；在允许本机测试网络及隔离容器的环境复测通过。一次最终前端专项 npm 启动器异常退出，随后直接运行 Playwright 完成复测；没有放宽测试断言。
