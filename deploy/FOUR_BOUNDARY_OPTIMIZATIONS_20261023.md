# 四项边界优化与验收（2026-10-23）

已完成引用与结论一致性、信息不足分类、识图边界、异常处理与页面反馈的代码优化，并更新本地前后端容器。本轮验证使用本地模型、HTTP、数据库替身及浏览器接口拦截，没有向外部模型发送新材料，没有调用向量模型。

## 行为变化

### 引用与结论一致性

- 引用存在仍须通过结论支持度审核：保留数量与单位、程度与确定性、适用条件等检查，补充因果强度检查。仅有相关性或倾向性描述，不能直接支持肯定的因果表述。
- 每条结论只使用审核指定的证据；其他引用中出现因果词，不会自动授权当前结论。
- 补充“仅在”“只在”等条件边界；拒绝无依据的谓语后，不再把前面的孤立名词（例如“饮料。”）作为有依据的回答保留。
- 保持否定因果句的完整性，避免切分后把“不能说明导致”误当成肯定因果。
- 本地规则是补充防线。结论语义是否被证据支持，仍依赖大语言模型审核，不能由词语匹配证明。

### 信息不足分类与补检

| 审核状态 | 含义 | 审核触发的行为 |
| --- | --- | --- |
| `SUFFICIENT` | 输入和知识足够 | 不因信息不足追加检索 |
| `MISSING_INPUT` | 缺用户事实 | 提示补充输入；不会因为结论条件失败而额外检索 |
| `MISSING_KNOWLEDGE` | 缺知识证据 | 可在现有预算内补检一次 |
| `MISSING_BOTH` | 同时缺输入与证据 | 分别列出缺项；可补检知识，仍保留输入缺口 |

`MISSING_BOTH` 必须同时有“用户输入：”和“知识证据：”开头的缺项。`needsMoreEvidence` 必须与知识缺口一致。知识补齐后可以从 `MISSING_BOTH` 转为 `MISSING_INPUT`，不能把新增证据当成用户事实。

审核上下文加入有长度上限的用户历史发言，明确最新输入优先；不把助手先前的猜测当作用户已提供的信息。新增用例覆盖输入已补齐、只缺知识、同时缺两者和补检后仍有缺项等状态。首次检索和无初始证据的旧兜底路径保持兼容；上表描述审核触发的补检，不表示所有检索都必须先经过审核。

### 识图边界

- 提示词明确少量可食剩菜仍是食物；污渍不能当作份量。遮挡导致无法判断内容时，不能据此认定空盘。
- 明确饮料属于食物；不透明容器不能用来猜配料、含糖量。包装食品须依据可见内容或可读标签判断。
- 多餐盘只识别可见食物，不虚构人数、克数或个人摄入量。
- `sceneType=UNCLEAR` 或 `imageQuality=UNCLEAR` 优先返回需要补充清晰图片的结果。新场景协议必须明确提供图像质量和食物布尔标记，避免 DTO 默认值制造空盘判断；无新场景字段的旧合法响应保持兼容。
- 保留低置信度候选不计分、未知油炸或高油属性不猜测等约束。新测试覆盖剩菜、饮料、包装、局部遮挡、多餐盘及仅有污渍的空盘。

这些测试向真实解析与评分代码输入构造的模型响应，验证协议、控制流程与不确定性处理；不等同于识图模型看真实图片的准确率测试。

### 异常处理与页面反馈

| 错误 | 直接接口响应 | 页面反馈 |
| --- | --- | --- |
| `REMOTE_TIMEOUT` | HTTP 504 | 可使用原图、原请求标识手动重试 |
| `MODEL_RESPONSE_INVALID` | HTTP 502 | 明确是模型格式无效；不归因为照片模糊或非食物，可手动重试 |
| `MODEL_REQUEST_LIMITED` | HTTP 429 | 等待服务限制解除，持续发生时检查服务额度 |
| `REMOTE_CONFIGURATION` | HTTP 502 | 提示管理员检查密钥、模型权限与连接配置 |
| `AI_BUDGET_EXCEEDED` | 保留已有预算响应 | 等待项目每日额度重置 |

远程 HTTP 429 和 402 分别归入服务限制/计费受限；未推断未经核实的供应商业务错误码。检查异常原因链后再采用通用模型错误，避免外层包装吞掉超时或配置错误。格式解析和字段错误使用明确的类型；异常摘要采用固定安全文案，不向页面或任务摘要泄漏原始响应和密钥。

任务状态允许保存新增错误码，失败不产生分析结果，保留请求标识。浏览器用例验证手动重试复用文件与请求标识、限额/配置失败不诱导反复上传、刷新恢复原因、终态停止轮询，以及手机窄屏提示与按钮的布局。
