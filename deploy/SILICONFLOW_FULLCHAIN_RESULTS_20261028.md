## 限流与停止行为

50 档后段建议生成已连续出现 429。原脚本的停止检测读取带助手 request ID 的事件，而后台图片消费者没有这一 ID，因此漏掉了该批内部的 429；随后首张边界图的显式 HTTP 429 才触发自动停止。本轮没有继续发送剩余 40 题，但仍额外产生了这 1 张边界图的 2 次受限尝试。

停止后已补充脚本检查：后台 HTTP 操作窗口也作为保守健康停止信号，不再依赖助手 request ID。只停止和取消本轮请求，不把其他用户结果归入质量指标。用本次 50 档的 192 条实际 HTTP 记录做本地回放，检测到 10 次 429，应在该批后直接停止；脚本本地 8 项用例通过，没有重跑真实模型。实际执行的原脚本快照保持在证据批次中，不能将回放修复当成本轮原本就及时停止。

当前证据不足以区分供应商 RPM、TPM 或并发限额，应核对该账号、该模型的配额及允许记录的限流响应信息。本轮既包含本地准入等待，也有上游明确拒绝；只增加消费者、许可或超时不能解决上游 429。
