# 图片与任务生命周期维护

## 实现范围

- `TaskLifecycleMetrics` 每 30 秒在维护线程池采样：数据库内图片 payload 总字节、失败 payload 字节、最老图片年龄、最老失败图片年龄、引用图片数量、有效未发布 Outbox 数量/年龄及等待恢复任务数。Prometheus 抓取只读内存快照。
- payload 字节与 512 MiB 准入预算保持同一口径，仅计 `input_image`，不包含引用图片、WAL、TOAST/MVCC 开销、索引及备份。图片年龄从任务创建起算，失败年龄从失败状态更新时间起算。
- 数据库增长每 5 分钟采样一次：当前库大小、三个任务表含索引/TOAST 的大小、估计死元组，以及整个 PostgreSQL 实例的累计 WAL 字节。死元组不等于精确膨胀率；WAL 不是 MealCheck 专属用量，统计重置可能使累计值归零。使用监控系统 `rate` 观察增长。统计权限不足时独立健康指标置零，不授予应用额外的管理权限。
- 采样异常保留旧值，健康标记与最后成功时间表明其新鲜度。Outbox 仅统计仍有图片的待执行任务，失败归档不误报为待发布积压。现有失败/死信监控继续使用 `TaskFailureMetrics`。
- 清理输出成功/失败次数、上次成功时间、启用状态和是否仍有批次。初次启动未执行清理不会在 26 小时窗口内误报缺失。
- 分批清理使用同语句行锁与 `SKIP LOCKED`，保护正在重试的行；成功请求/删除后墓碑继续保留。清理失败 payload 不改动失败时间；有效 PENDING/PROCESSING 图片不进入清理。
- 联合备份在完成远端校验后输出 `mealcheck_backup_artifact_bytes`。失败运行保留最后成功的体积和时间。体积为本地备份目录内文件字节和，不是云端加密后占用或计费体积。沿用现有 Pushgateway，按备份周期观察增长。

## 告警与操作

规则覆盖图片预算使用超过 80%、生命周期采样过期、未发布 Outbox 超龄、清理异常/超过 26 小时未成功、数据库增长采样不可用。原有死信、任务超龄和备份失败告警保留。`lifecycle-alerts.test.yml` 验证空间告警触发及释放后的恢复。

预算告警先查看失败字节及清理策略，再检查消费者和依赖状态。按原保留期限清理，不因达到阈值自动缩短数据保留期；不自动删除成功幂等身份、不执行 VACUUM FULL、不重置统计。大量死元组或 WAL 增长应结合 autovacuum、事务年龄、检查点和备份周期分析。

## 验收边界

使用隔离 PostgreSQL 与测试图片；不清理现有业务数据库或上传目录。验证失败 payload 占满预算、清理后释放、重新接单、成功请求重放不重复保存、并发重试锁定行不被删除，以及指标异常保留旧值。告警使用合成时间序列验证，不向外部通知渠道发送测试消息。
