# 50 人突发配置

2026-10-16 更新：未完成任务默认及本兼容覆盖文件均已提高到 200，并增加 512 MiB 数据库图片暂存预算。上传入口仍为 64、消费者仍为 40、AI 调用节奏不变。下文 64 个任务名额和 50 张 56.47 秒均是历史验收条件；新容量、状态及恢复说明见 [200 张容量说明](../QUEUE200.md)。200 个积压名额不等于 200 人同时上传或一分钟完成。

2026-10-15 起，这套容量参数已提升为应用、普通 Compose 和生产 Compose 的默认值，正常启动无需额外加载本覆盖文件。该文件继续保留以兼容已有命令；下文部署说明适用于显式使用该覆盖文件的环境。现有环境变量可能覆盖主配置默认值，更新后仍需重建和重新创建容器。

当前 Max 模型的本地隔离验收：50 个账号首次同时上传，50/50 接受并成功保存，最后一个在 56.47 秒内完成。使用 1024×1024、约 200～240 KiB 的合成餐食 JPEG；这是一轮验收，不是公网或供应商 SLA。

这个可选覆盖配置配套调整入口、临时空间、任务名额和模型调用节奏。40 是业务消费者数量，不代表每秒向模型发送 40 次请求；所有实例通过数据库共用 400 毫秒最小调用间隔、42 个许可和每分钟 120 次准入。识别、建议、助手、周报与重试共用这些限制。

部署时，在项目根目录给既有生产 Compose 命令追加 `-f deploy/burst50/compose.yml`，并使用本次修复后构建的后端。先用原生产环境文件执行 `config --quiet` 检查组合配置，再沿用项目的备份和部署流程。源码或 `.env` 变化后需要重新构建/创建容器，不能只重启旧容器。本次任务没有部署生产。

覆盖配置不设置供应商地址、模型或密钥，继续使用你的阿里云 Max 配置；也不放宽生产的个人/全站日预算。输入输出价格和日费用预算仍由实际环境提供，不能照搬隔离测试中的凭据或预算。

资源与范围：后端 1.5 CPU / 1 GiB，JVM 堆比例沿用生产默认 45%；前端内存限额 1.5 GiB、上传缓冲 1 GiB、未设置前端 CPU 硬配额；上传临时文件使用既有磁盘卷。64 个名额是短时突发容量，不能解释为持续 50 人每分钟均能处理。1 GiB 后端临时空间预算同时检查预留和已落盘字节，因此 50 张接近 10 MiB 的大图可能提前被拒绝；本次没有验证这种大小的文件，更没有证明它们能在一分钟内完成。

`nginx.conf` 与 `frontend/nginx.conf` 的全局 multipart 连接名额现均为 64；基础 Nginx 配置变更后应同步派生文件，避免安全头或代理规则漂移。
