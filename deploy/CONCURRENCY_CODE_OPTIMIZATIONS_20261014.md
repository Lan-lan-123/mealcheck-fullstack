# 纠错画像增量更新与任务领取事务优化（2026-10-14）

本轮按用户指定完成两个代码改进，保留当前账户锁顺序、修订号、执行 token、租约、幂等与提交护栏。没有新增数据库迁移或修改并发上限。

## 纠错后增量更新画像

`MealCorrectionService` 在修改受管餐食实体前捕获不可变 `MealContribution`：旧评分、食物名称、风险标签和目标。保存并 flush 新餐食后，在同一事务和账户锁内调用 `UserDietProfileService.replaceMeal`。

已初始化且统计一致的画像按旧、新餐食的贡献差额更新：

- 餐数不变，总评分减去旧评分、加上新评分，重新计算平均分。
- 食物、风险、目标计数按差额更新；保留重复项的计数语义，去除归零项。
- 未改变的计数保留原字典顺序，避免因减后再加改变相同频次条目的排序。
- 更新常见食物/风险、首选目标和摘要，继续使用原有画像版本控制。

缺失、未初始化、无法解析或与旧餐食贡献不一致的画像，按已经保存的新餐食全量重建，防止错误增减或重复计入。该兼容路径不是每次纠错的正常路径。聚合 JSON 仍需解析和写入；本轮消除的是正常纠错时对全部历史餐食的加载、JSON 解析和聚合。

画像替换要求已有事务（`MANDATORY`），餐食、画像、审计和任务缓存一起提交或回滚。上传、纠错、删除继续按账户锁串行维护该用户统计。

## 事务只领取元数据，提交后读取图片

`MealAnalysisRequestStore.take` 将 `SELECT r.*` 改为明确的任务元数据列，领取事务不再返回 `input_image`、结果 JSON 等大字段。`Work.imageMetadata` 只有 MIME、扩展名、尺寸和文件名，图片内容为空；工作执行和续租注册不会持有该图片的字节数组。

两种 Worker 都统一在领取事务提交后调用 `loadImage`：

- 内联图片：独立查询图片字节，过滤用户、任务 key、执行 token、处理中状态及有效租约。
- 引用图片：先验证仍拥有该任务和引用，再读取存储文件/对象。
- 两种读取完成后再次验证 token、租约、状态及引用，阻止读取期间删除、过期或替换的旧执行进入模型工作。
- 图片读取声明 `NEVER`，误在活动事务内调用会立即拒绝，避免把图片 I/O 再放回账户/任务锁事务。
- 正常失去任务所有权使用专门异常，Worker 计为 `fenced` 后停止；RabbitMQ 正常确认该旧消息，不修改新执行状态、不把它误报为模型失败或送入死信。
- 有效任务的真实存储/数据库错误继续按原规则记录失败；保存阶段仍独立校验 token 和有效租约。
