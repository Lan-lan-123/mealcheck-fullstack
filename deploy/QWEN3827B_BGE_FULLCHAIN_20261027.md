## 解释边界

请求完成、模型内部复核成功、有引用，分别统计；这些指标不能单独代表语义正确。

图片和边界验收依据预先冻结的合成标签，问答由助手结合实际输出和项目引用逐题复核，均不属于独立人工金标准。50 账号测试是同一批五张合成图片的一次突发上传，不能直接推断长期生产容量或不同真实照片的准确率。

无法识别图片按预期返回 `IMAGE_UNCLEAR` 的 HTTP 400，属于边界验收结果，不能直接计作系统失败。配置的许可上限不等于实际达到的模型 HTTP 并发峰值。

## 优先处理顺序

1. **额度及停止判据**：将供应商权限/额度失败传递为明确原因；修复复核失败被路由为知识不足。测试脚本目前只检查部分上游状态及业务失败，漏掉被 HTTP 200/SSE 正常结束包装的上游 403，因此额度耗尽后仍发送了后续请求。实际未超出 500 次上限，但持续失败自动停止本项不能判为通过；下轮应在首个不可恢复的权限/额度错误即停止，普通连接故障按既定有限重试处理。
2. **剩余语义问题**：补充“未知＋若感觉油腻”条件句，保留跨食物与跨属性事实检查；消除原味名称推断单一配料、未经选择的低脂目标及油脂补偿暗示。
3. **复核可靠性和选参**：检查复核请求长度、结果约束、60 秒 HTTP 超时及传输异常诊断；保留当前证据，再做额度充足时的成功复核尾部采样。本轮不支持通过一味增大总预算解决问题。
4. **性能补测**：先有小额可靠性通过，再对问答并发与较长时间、更多不同图片的持续负载单独分配预算。50 次突发全部完成是积极结果，但不能据此宣称生产容量已达上限。
