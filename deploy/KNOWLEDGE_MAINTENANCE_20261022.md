# 知识管理：重建预览、内容恢复与编辑冲突保护

日期：2026-10-22，Asia/Shanghai。

## 管理员操作

管理员进入「RAG 知识库」：

- 「重建系统 RAG 知识库」「仅生成选中知识」先展示影响预览，再提交任务。预览包括正文新增、更新、删除数量，目标模型和维度，受影响的系统知识人工修改，以及两阶段的向量请求估算。
- 向量模型配置中，需要重建的「应用配置」同样先展示预览。同一向量空间的连接凭据更新仍沿用原有连接应用流程。
- 任务历史的「重新提交」会按当前选择重新预览；局部任务保留仍存在的目标 ID。应用已测试的待用模型使用向量模型配置入口，避免隐式选择另一份配置。
- 每条知识可打开「内容历史」，全局入口可查看全部历史及已删除知识。选定历史版本后并列显示历史正文和当前正文；填写恢复原因后恢复。恢复只使用历史标题和正文，按当前生效模型重新生成向量，不复用旧向量空间。
- 保存和删除携带所见的正文版本。另一项操作先修改了同一条知识时，旧操作返回冲突；页面保留编辑草稿，可比较最新正文后重新编辑。

系统 Markdown 的数据库切片编辑仍不回写源文件。显式源同步会按部署携带的 Markdown 恢复正文，管理员新增的其他来源知识保留。预览会列出受影响的人工修改，历史可以用于比较与恢复。本文没有将维护模型改为按主题编辑源文件。

## 预览和取消边界

预览不调用 embedding、重排或回答供应商。估算使用标题、正文 UTF-8 字节数加请求余量，不是供应商计费 token，也不是费用报价；接口重试可能增加请求数，有效暂存可能减少请求数。

预览指纹绑定源文件、实际切片清单、长度参数、知识库数据修订号、当前和目标向量签名；待用配置另绑定不可变配置 ID。提交时重新核对，变化返回 409，要求重新预览。排队任务在执行源同步前再次核对；实际读取源文件时还会核对正文 SHA。

源同步取得租约时核对预览所见的源数据修订号。准备向量期间发生内容修改仍由原有发布检查拦截。预览失效任务不提供继续旧计划的重试按钮，应重新预览并提交。

源同步和目标向量激活是两个发布阶段：

1. 源同步发布前取消，可以阻止该任务发布所准备的正文与切片；同步续租和发布均核对任务执行凭证，并维护任务租约。
2. 源同步已提交后取消，不撤销已发布正文或切分。目标模型切换前继续使用当前生效向量方式；页面明确显示这一边界。

历史任务和自动维护保留兼容路径。原有同步源管理 API 仍为显式管理入口，本次没有取消这些接口。

## 存储与一致性

新增 Flyway `V44__knowledge_content_history.sql`：

- `knowledge_chunks.content_revision` 为单条正文修订号。
- `knowledge_content_versions` 保存正文和来源快照、动作、操作者、原因和记录时间，不保存向量或模型密钥；删除知识不会级联删除历史。
- 数据库触发器覆盖管理员修改及系统源同步，快照与实际写入在同一事务提交。纯向量、用量与命中统计更新不生成正文历史。
- 对升级前已存在知识建立 BASELINE 快照；无法补造启用前的历史。
- 乐观更新与删除在 SQL 中比较正文版本，防止多个实例上的管理员互相覆盖。恢复在向量准备前后检查当前版本，并检查向量签名。已删除来源键若已被新知识占用，返回冲突，要求人工比较合并。
- 重建任务增加 `preview_token`，没有该字段值的历史任务沿用已有恢复机制。

内容历史不自动清理。后续若增加保留策略，需同时考虑删除恢复窗口和历史审计需求。

## API 变化

- `POST /api/admin/knowledge/indexing/preview`：使用 `mode`、可选 `chunkIds` 或 `splitterStrategy` 获取预览。
- `POST /api/admin/knowledge/indexing`：同一参数附带 `previewToken` 提交；缺失或过期返回 409。
- `POST /api/admin/knowledge/embedding-settings/preview`：携带配置 `version` 预览待用模型；需要重建的 apply 请求附带 `previewToken`。
- 知识列表增加 `contentRevision`；PUT 内容附带 `expectedRevision`、可选 `reason`。DELETE 通过查询参数携带 `expectedRevision`。
- `GET /api/admin/knowledge/content-history`：支持 `chunkId`、`deletedOnly`、`page`、`size`。
- `GET /api/admin/knowledge/content-history/{id}`：历史快照、当前正文及当前修订号。
- `POST /api/admin/knowledge/content-history/{id}/restore`：携带 `expectedRevision` 和非空 `reason`。

这些管理接口仅管理员可用。前后端应一起部署；旧页面没有内容修订号或预览 token 时需要刷新。
