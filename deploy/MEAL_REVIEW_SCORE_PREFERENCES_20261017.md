# 不确定项快捷核对、评分明细与饮食偏好（2026-10-17）

三项功能已完成源码和本地验证。本轮没有调用真实模型，新增供应商 token 为 0；没有更新现有业务部署或业务数据库。

## 用户入口与行为

### 不确定项快捷核对

在餐食分析结果或历史详情点击“核对并纠正识别”。复用现有纠错保存入口，不重新识别图片，也不调用模型生成建议。

- 除低于 80% 的模型自报置信度外，也识别说明中的明确歧义，例如“可能是牛奶或豆浆”，以及有相关名称/线索但尚未确认的油炸、高油属性。
- 白色饮品可快捷选择牛奶、豆浆或不确定；其他食物可确认名称与分类，或选择不确定，并保留直接编辑入口。不会因奶油蛋糕、奶酪等名称中含“奶”就给出牛奶/豆浆选项。
- 油炸与高油风险分别选择是、否或不确定。未知保持 null，与 false 区分；未知风险不按已确认风险扣分。
- 无法确认名称时保存“未确认饮品”或“未确认食物”，不再把原猜测当作确定的牛奶、豆浆等基础来源；重开后仍提示核对。原识别和纠错前后对象沿用现有审计快照保留。
- 修改名称时重置风险属性；确认原名称不变时保留原属性。待核对项需明确确认核对内容再保存，不会静默当作核对完成。
- 这些提示是确定性名称/说明规则，不能覆盖所有视觉歧义；高置信度也不等于真实正确概率。

### 评分明细

在完整分析或餐食历史详情中展开“查看评分明细”。

- 明细来自实际执行的评分分支，包括基础分、结构、饮品、种类、目标、风险、封顶、保底和 0–100 范围调整，不由 AI 编造解释。
- 明细保存规则标识、说明、实际加减分和关联食物，总和必须等于最终分数；待核对风险以 0 分项目明确说明暂不据此扣分。
- 结构评分公式和版本保持 structured-foods-v5；本次只增加执行轨迹与展示。
- 新图片分析、手动记录、主动纠错都保存明细 JSON 快照。历史读取使用该快照，不用当前规则重算旧分数；没有快照的旧记录显示未保存明细。
- 纠错结果包含修改前后分数及版本，页面即时显示差值；版本变化时注明差值包含版本影响。详细规则可在纠错后的完整结果里展开。

### 饮食偏好与忌口

入口：“饮食目标”页面中的“饮食偏好与忌口”。

- 支持不限、蛋奶素、纯素；分别保存忌口和不喜欢的食材。两类各最多 20 项，每项最多 40 字，去重并清理首尾空格。
- 支持保存、重载、清空。清空表单后需保存才生效；多页面修改用版本号检测冲突，避免旧表单覆盖新设置。
- 接口只使用当前认证用户身份，不接受客户端指定其他用户。偏好随账号删除级联清理。
- 设置应用于后续单餐建议（包括规则建议及纠错）、助手普通/工具调用/流式回复，以及规则和多 Agent 新周报。用户明确设置优先于历史推测。
- 提示词携带设置，返回内容再经过保守名称检查；命中已设置食材或对应素食规则中的具名食材时，相关文本替换成不包含具体食材的通用核对建议。不会为此再请求模型。
- 启用偏好约束的助手请求会先完整生成并检查，再向流式界面发送已检查文本，避免冲突内容先显示。没有偏好设置时保留原逐段流式行为。
- 修改偏好会使当前周报及任务过期，前端报告缓存失效；历史文字保留。已有食物记录及结构分数不因偏好被修改。

限制：名称检查是保守兜底，不能全面理解同义词、隐藏配料、复合菜成分或过敏原；也可能把含有禁用名称的事实陈述或否定句替换掉。不能将该功能解释为配料或过敏安全保证。本轮验证了数据与逻辑链路，没有付费复测真实模型的个性化表达质量。

## API 与数据库

- GET/PUT `/api/profile/diet-preferences`：`{style, avoidFoods, dislikedFoods, version}`；首次默认不限、空列表、version=0，保存后版本递增，旧版本返回 409。
- 餐食详情新增可空 `scoreBreakdown`；分析结果在 `evaluation.scoreBreakdown` 返回明细，纠错结果另含 `scoreChange`。
- 前端运行时校验保留旧响应兼容，检查签名整数加减分、明细合计与外层分数一致、纠错后分数与结果一致。
- V34 新增 `meal_records.score_breakdown_json`；V35 新增 `user_diet_preferences`，user_id 引用 users 并级联删除。无需批量重算或覆写历史餐食。
- 正常重新构建并启动后端时由 Flyway 执行迁移，同时重建前端即可展示入口。本次仅在 Testcontainers 独立临时数据库验证迁移，未向原业务数据库执行。
