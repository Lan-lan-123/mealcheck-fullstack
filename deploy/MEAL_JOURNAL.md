# 餐食记录、行为目标、行动计划与助手反馈（V28 基础，含 2026-10-13 优化）

## 使用入口与统计口径

- **饮食记录**：手动记录 / 补记，填写实际用餐时间、餐次和食物；“修改用餐信息”可调整已有图片或手动记录的时间、餐次和备注。创建时间保留，用餐时间独立保存。填写无时区的时间时按项目业务时区解释，当前为 `Asia/Shanghai`；数据库时间仍使用 UTC。
- 图片记录初始时间沿用创建时间，餐次为“未指定”，标注“时间待确认”；历史记录也采用此方式。确认后才移除提示。手动记录使用本地结构评分与建议，不调用图片识别或真实模型，不消耗上传频率额度。
- **餐次记录状态**：未记录=`UNKNOWN`，明确未吃=`SKIPPED`，有对应餐次记录=`RECORDED`。已有餐食不能直接标为未吃；补记相同日期、相同餐次会清除该餐次的未吃标记。撤销标记后恢复未知。
- **饮食目标**：保留均衡、减脂、增肌等方向，新增每周记录天数和每日记录餐次。周周期为周一至周日；每日餐次按早餐、午餐、晚餐、加餐去重，同一餐次多条记录只计一次，未指定餐次不计每日目标。每周有记录天数按日期去重。目标进度从持久化餐食记录计算，补记、修改和删除后同步变化。
- 每周目标数量为 1–7 天，每日目标为 1–4 餐；同类型的启用目标不能有重叠日期。首尾不足完整一周时，仍使用用户设定的目标数量，界面展示实际周期范围，可调整目标数量或周期。每日目标同时展示目标周期内已达标天数与已过去的有效天数。
- **行动计划**：餐食完整建议、完整助手回答和周报下周建议均支持“加入计划”。保存时可把原建议改成具体行动，并设定日期。计划支持完成、跳过、重新打开、调整日期 / 内容和执行备注。来源关联用户自己的餐食或助手消息；周报建议记录来源周期，保留行动文本副本。
- 默认计划列表显示过去 30 天至未来 90 天，可用计划日期筛选回顾其他周期，每次最多 366 天。周报中的计划完成、跳过、待执行按**计划日期**归入报告周期，完成时间另行保留；修改计划日期会改变其统计归属。
- **趋势与周报**：按实际用餐日期统计评分、分类和风险，并显示有记录天数 / 总天数、三餐未知数量、明确未吃数量、目标进度和计划执行数量。加餐单列，未指定餐次可以增加记录天数但不能代表任一三餐已记录。记录很少时提示样本不足，所有食物和评分统计只代表已记录餐食。
- **可选营养估算**：继续默认关闭，并明确提示不准确。份量、热量和宏量营养估算不参与行为目标达标判断。修改时间、餐次、备注使用独立版本，不会使已有营养输入失效；纠正食物仍按原有食物版本使估算失效。

## 助手流式与取消

`POST /api/assistant/stream` 使用 SSE，先返回 `queued` 与请求 ID，再按 `meta`、`delta`、`complete` 或 `error` 事件返回。`meta` 含会话 ID 与请求 ID，`delta` 含增量文本，`complete` 含持久化回答消息 ID。旧的 `/api/assistant/ask` 和 `/api/chat` 完整响应接口保留。

配置真实模型时直接消费兼容 OpenAI 的 `/chat/completions` 流，界面随内容到达更新，不对完整回答模拟逐字输出。流式路径使用现有确定性工具、知识检索和会话上下文准备；旧完整响应路径继续保留模型 Function Calling。未配置模型时，仅发送本地规则建议，通常一次返回全部内容。

取消等待会中止浏览器请求，并调用 `DELETE /api/assistant/requests/{requestId}`。服务端只允许取消本人请求，关闭上游读取、打断任务、释放并发准入；已派发的模型请求可能产生费用，取消不保证退款。流式请求使用现有预算、并发与总期限约束，已显示内容不会因重试重复发送。没有最终 usage 时不编造实际用量，按已有预算策略保守结算。

会话历史保留部分回答并标为 `CANCELLED` 或 `ERROR`，不作为完整回答进入记忆或保存为计划；摘要游标仍按实际数据库消息行数推进，避免反复处理同一段历史。完整回答与对应提问在同一事务保存，账户与会话删除后不能由迟到回答重新建立数据。Nginx 关闭 API 响应缓冲，Spring Security 允许已通过初次鉴权的异步响应分派。

回答反馈可选择有帮助 / 无帮助，以及内容或识别错误、答非所问、解释不清、服务异常等类型。反馈关联回答消息和请求 ID；后台日志以相同请求 ID 记录开始、完成或异常类型，不记录问题正文或密钥。反馈详情在展开时读取，避免打开长会话时逐条发起额外请求。

## 新增接口

所有接口要求登录，所有关联资源检查所属账户。用户不存在返回 401，资源不属于用户或不存在返回 404，版本冲突或餐次状态冲突返回 409，输入不合法返回 400。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/meals/manual` | 手动记录 / 补记，`occurredAt`、`mealType`、`goal`、`foods`、可选 `note` |
| `PUT /api/meals/{id}/metadata` | 更新实际时间、餐次、备注；使用 `expectedVersion` 与 `metadataVersion` |
| `PUT /api/meals/skipped` / `DELETE /api/meals/skipped` | 确认 / 撤销未吃，提交 `day` 与 `mealType` |
| `GET /api/meals/coverage?from=日期&to=日期` | 记录覆盖、每日餐次状态、目标进度与计划汇总 |
| `GET /api/profile/behavior-goals` | 行为目标列表 |
| `POST /api/profile/behavior-goals` / `PUT /api/profile/behavior-goals/{id}` | 新增 / 修改目标；字段 `kind`、`target`、`startDate`、`endDate`、`active`、`expectedVersion` |
| `GET /api/plans?from=日期&to=日期` | 计划列表，可省略日期使用默认范围 |
| `POST /api/plans` | 创建计划及来源关联；周报来源提交 `sourcePeriodStart`、`sourcePeriodEnd` |
| `PUT /api/plans/{id}` | 修改计划及状态，使用 `expectedVersion` |
| `POST /api/assistant/stream` | 流式回复，问题长度 1–4000 字 |
| `DELETE /api/assistant/requests/{requestId}` | 取消本人正在生成的回复 |
| `GET` / `PUT /api/assistant/messages/{id}/feedback` | 读取 / 保存回答反馈 |

餐食、目标和计划变更使用账户锁及事务；时间信息、行为目标、计划各自具有版本，避免并发编辑覆盖。日期范围最多 366 天；目标和计划列表按页查询，每页 1–100 项，并返回总数；统计所用目标按日期范围完整读取。

## 迁移与验证

Flyway `V28__meal_journal_goals_and_action_plans.sql` 增加餐食时间、餐次、来源、备注和版本，回填已有记录的时间，建立实际时间查询索引；新增餐次声明、行为目标、行动计划和回答反馈四张表，并给助手消息增加请求 ID 与完成状态。

迁移保留已有账户、餐食和历史周报。用户之后修改餐食时，按受影响日期标记相关周报过期并保留原快照；行为目标与计划进度在当前报告读取时更新。详见 [代码优化说明](CODE_OPTIMIZATIONS.md)。私有新增数据随账户删除；删除餐食或助手消息后，计划保留文本并清除其已删除来源引用。

数据库测试覆盖业务时区午夜边界、历史补记、独立版本、并发修改、权限、未知与未吃、目标周期与餐次去重、计划执行及来源、反馈关联和迁移保留历史。HTTP 测试验证真实 SSE 异步响应。模型桩测试验证 UTF-8 分段到达、结束前显示、取消连接、期限、预算结算和不重放已输出内容。

浏览器验证覆盖移动端补记、时间修改、未吃状态、目标保存、计划打卡 / 跳过 / 调整、SSE 到达即显示、取消、反馈和保存助手计划。部署验证使用临时账户和标明的合成餐食，并在结束时通过账户删除清理数据。

**真实 AI 助手测试按本轮要求暂缓**：没有调用真实模型，未验收真实服务商的流式兼容性、答案质量或计费准确性。当前本地 Docker 未配置真实 AI 密钥，助手使用本地规则建议。
