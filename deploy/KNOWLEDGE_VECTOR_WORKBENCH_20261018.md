# RAG 向量工作台

管理员进入「RAG 知识库」即可查看向量工作台。前后端需一起更新，后端启动时通过 Flyway 执行 V38；更新本身不会调用向量模型或重新生成现有向量。

## 使用

- 统计卡片展示知识总数、匹配当前配置、语义模型、本地生成和需要更新的条数。统计来自实际的 `embedding_signature`，不以当前配置推断所有历史记录。
- 状态分布图可逐条勾选；也可切换明细列表查看模型名称、维度和最近向量更新时间。绿色表示匹配配置，蓝色表示正在处理，橙色表示需更新。
- 支持标题或 ID 搜索、按生成方式和状态筛选、勾选筛选结果以及清空选择。选择跨筛选和分页保留，每批最多 500 条。
- 「仅生成选中知识」只为选中条目生成向量，跳过 Markdown 源同步和切分；不改知识正文、未选中的向量或生效模型。选中记录在生成期间被编辑时，暂存向量作废并按新内容重新生成。
- 选中项必须使用当前生效方式；从本地切换到语义模型，或反向切换，使用「重建系统 RAG 知识库」。仍以整库暂存和原子切换保持向量空间一致。
- 后台任务自动分批处理，展示真实暂存进度；失败保留原向量和暂存结果。对同样的选中条目重新提交，可继续失败任务。

历史记录的向量更新时间没有可靠数据，保留为空并显示「历史生成时间未记录」。新写入或重建时记录时间，不使用内容更新时间冒充生成时间。
新时间字段使用 `TIMESTAMPTZ` 存储绝对时间，前端按上海时区显示。

逐条状态图最多展示前 2000 条并明确提示截断，统计仍覆盖全部知识；下方原有知识分页列表也支持勾选。

## 接口与存储

`GET /api/admin/knowledge/indexing` 在原配置和任务信息之外增加 `inventory`，包含全库 `counts`、逐条 `chunks` 和 `truncated`。逐条数据包含实际签名、模型、维度、时间、是否匹配以及当前任务暂存状态，不包含接口密钥。

`POST /api/admin/knowledge/indexing`：

```json
{"mode":"SEMANTIC","chunkIds":[1,2,3]}
```

不传 `chunkIds` 保持原有整库重建；传空数组拒绝。请求校验有效 ID、数量、生成方式、生效签名及物理存储维度。HTTP 202 返回持久化任务。

V38 为任务增加范围和完成条数快照，新增持久化选中目标表和向量更新时间。局部任务沿用现有任务租约、内容哈希校验、暂存表和重试机制。最终发布只更新选中目标；全量发布保持原有原子列切换。缓存版本随向量变化更新。

## 验证

- PostgreSQL / pgvector Testcontainers 验证迁移、选中项隔离、失败续传、编辑后重新生成、模型变化拦截、缓存版本更新和整库本地/语义模式切换。
- 浏览器覆盖分布图勾选、跨筛选保留、批量请求、进度、禁止部分切换，以及手机明细列表；模型调用使用测试替身，不消耗真实模型额度。
- 测试数据库独立于项目业务数据库；本次没有对业务知识执行重建。

验证结果：后端完整单元测试 402 项、数据库集成测试 20 项、前端单元测试 79 项、浏览器回归 15 项通过，类型检查和生产构建通过。最终时区字段涉及的 11 项数据库用例另行复测通过。
